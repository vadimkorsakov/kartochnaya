# Этап 6: esbuild и первые ES-модули v0.45

База ветки `refactor/v045-esbuild-foundation` — актуальная `main`,
`96d8c1ecfc39c9109fb5d5351fa34c6d49949ace` (merge PR #6).
Исторические документы этапов 0–5 описывают прежнюю побайтовую сборку;
актуальный порядок работы описан здесь. Этап 7 не начат.

## Назначение и границы

Прежний сборщик вставлял три JavaScript-фрагмента по текстовым маркерам.
У компонентов не было настоящих импортов и экспортов. esbuild **0.28.2** из
официального npm registry впервые разрешает модульные зависимости и собирает
их в автономный браузерный скрипт. Версия точно закреплена в devDependencies
и lock-файле; чистая установка проверяется через `npm ci`. Требование проекта
Node.js >=22 и `.node-version` 24.19.0 сохранены. Runtime-библиотеки не добавлены.

Математика, мутации, интерфейс, события, форматы JSON и схема IndexedDB сохранены.
`src/editor.js` остаётся монолитом с прежним strict IIFE. Его единственные изменения:
два импорта перед IIFE и удаление двух прежних маркеров. CSS и HTML-шаблон не изменены.

## Карта зависимостей и аудит инициализации

| Компонент | Экспорты / зависимости | Область и порядок |
| --- | --- | --- |
| `core/primitives.mjs` | `html`, `clamp`, `fmt`; зависимостей нет | Чистые объявления до запуска IIFE |
| `core/colors.mjs` | `rgbHex`, `hexRgb`, `hsvRGB`, `rgbHSV`, `rgbHSL`, `hslRGB`, `normalizeHex`, `cpFormatValues`; явно импортирует `clamp` | Чистые объявления до запуска IIFE; тела исторических функций сохранены |
| `editor.js` | Явно импортирует все 11 функций; публичных экспортов нет | Прежний IIFE замыкается на импорты; нет передачи через `window`/`globalThis` |
| `core/gradient-model.js` | `gradientStops`, `gradientGeometry`, `gradientSample`, `addGradientStop`; использует `uid`, `clamp`, `rgbHex`, `hexRgb`, `normalizeHex` | Legacy-фрагмент восстанавливается между `hexAlpha` и `getGradientStop` внутри IIFE |
| `uid`, `clone`, `app` | Локальные зависимости редактора | Остались в IIFE без изменений; `uid` по-прежнему обращается к `globalThis.crypto` |

`html`, `clamp`, `fmt` раньше объявлялись непосредственно после `clone` и до
`types`/`app`. Их перенос не добавляет выполнения пользовательской логики:
инициализируются только функции. Цветовые function declarations раньше были
hoisted внутри IIFE. Теперь функции доступны через внешнюю лексическую область
к моменту его вызова. Циклических импортов и нового асинхронного запуска нет.

Два объявления каждой из `fitCanvas`, `applyZoom`, `renderSlideStrip`, `changeSlide`
сохранены и в исходниках, и в bundle. Действуют прежние поздние объявления,
поднятые в ту же область функции. Их нельзя объединять при следующей миграции
без отдельного исследования поведения.

Порядок runtime-обёрток сохранён: сначала мобильные обёртки `drawTextGlyphs` и
`paintText`, затем boundary-обёртки `paintDocument`, `drawTextGlyphs`,
`openInlineText`, `positionInlineText`, `closeInlineText`, `refreshInspector`,
`setSelected` и мобильных панелей. Capture-обработчики Undo/Redo, закрытия вкладки,
кадрирования и меню остаются на прежних позициях относительно остальных событий.
Pointer/touch-регистрации и прямые обращения к `window`, `visualViewport`,
`globalThis.crypto` не переписаны.

`init()` вызывается на прежнем месте до позднего мобильного/boundary-кода.
Его первая операция — `await openDB()`. Остаток синхронного скрипта успевает
зарегистрировать обработчики и обёртки до продолжения инициализации после await.
Сборщик не переносит этот вызов. Проверка исходников сравнивает **все оставшиеся
legacy-операторы побайтово** с историческим скриптом после удаления двух блоков
и импортов. Это защищает и порядок обёрток, и регистрацию событий; браузерные
проверки дополнительно контролируют фактическое поведение.

## Единственный путь сборки

1. `scripts/compile-javascript.mjs` читает актуальный `src/editor.js`.
2. Проверяет единственный оставшийся маркер, его соседей и исходную позицию;
   буквально вставляет `core/gradient-model.js` в прежний IIFE.
3. Передаёт восстановленный entrypoint через esbuild `stdin` с `resolveDir` и
   `absWorkingDir`, указывающими на `src/`. Импорты разрешаются из этих исходников.
4. Использует `bundle: true`, `platform: 'browser'`, `format: 'iife'`,
   `target: 'es2022'`, `minify: false`, `treeShaking: false`, `sourcemap: false`,
   `charset: 'utf8'`. Banner `"use strict";` сохраняет strict-семантику модулей
   и после упаковки; внутренний исторический strict IIFE также сохранён.
5. Проверяет единственный output, отсутствие runtime-импортов в metafile,
   динамических импортов, предупреждений, маркеров и сырого `</script`.
   JavaScript парсится как обычный скрипт через Node VM без выполнения приложения.
6. `scripts/compile-html.mjs` встраивает результат в прежний `<script>` шаблона,
   сохраняя остальные HTML/CSS-байты. `type="module"` не требуется.
7. `scripts/distribution.mjs` один раз компилирует HTML для обоих дистрибутивов.
   PWA ZIP содержит этот же `index.html` и 17 неизменённых исторических ресурсов.
   STORE, сортировка имён, DOS epoch и остальные правила детерминированного ZIP сохранены.

`es2022` соответствует уже используемому исходным редактором уровню языка/API:
optional chaining, nullish assignment, `Array.at`, `Object.hasOwn`. Canvas2D,
IndexedDB, Path2D, DOMMatrix, FontFace, Pointer Events не полифиллятся. EyeDropper
остаётся опциональным. Target не обещает поддержку старых браузеров без этих API
и не добавляет новых требований загрузки ES-модулей. Масштабных преобразований,
минификации и code splitting нет; размер читаемой сборки увеличился ожидаемо.

esbuild штатно экранирует HTML-чувствительные последовательности. Source-тест
добавляет во временный entrypoint строку `</ScRiPt><script><!--`, проверяет
единственный закрывающий тег в HTML и неизменность значения строки после сборки.
Внешние chunks, JS-файлы, CDN и sourcemap-файлы для запуска не нужны.

## Защитные проверки

```sh
npm ci
npm run test:source
npm run test:unit
npm run build
npm run build:verify
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:all
```

- `test:source`: восемь проверок. Неизменность 19 файлов, самого baseline-манифеста
  и трёх PNG; исходные HTML/CSS и тела функций; неизменность остального legacy-кода;
  реальные импорты/экспорты и единственность реализаций; ошибки маркеров;
  участие всех семи исходных компонентов; отказ при отсутствующих файлах,
  неверных импортах/экспортах/синтаксисе и runtime-импортах; безопасность HTML.
- Участие исходников проверяется на временных копиях содержательными изменениями:
  формулы clamp, префикса цвета/uid, позиции новой остановки, CSS-правил и заголовка.
  Комментарии и неиспользуемые выражения не считаются доказательством.
- `test:unit`: прежние 156 цветовых ожиданий непосредственно импортируют production
  `.mjs`; 50 градиентных ожиданий исполняют production legacy-фрагмент в VM с
  контролируемым `uid` и импортированными production `clamp`/цветами. Ожидания не изменены.
- `build:verify`: независимо компилирует актуальные исходники, повторяет компиляцию,
  проверяет классический встроенный JS, состав и канонические байты ZIP,
  независимо читает фактические ZIP entries и сравнивает `index.html` с HTML.
  Остальные 17 ресурсов проверяются по историческому манифесту. Source-тест
  также выполняет две полные сборки и раздельные HTML/PWA targets.
- Браузерный сервер отдаёт только новые `dist/`-артефакты. Проверки ресурсов
  специально различают изменяемый `index.html` и неизменяемые PWA-ресурсы.
  Исторический HTML никогда не подставляется при ошибке сборки: команда завершается
  ненулевым кодом. Старые файлы в `dist/` могут остаться от предыдущей успешной
  команды; выпускать их после ошибки нельзя, `build:verify` проверяет их против `src/`.
- `tests/module-bundle.smoke.spec.js`: документ с HTML-символами в названии, фигура,
  цвет, три градиентные точки, точные значения интерполяции, PNG, сохранение,
  reload и повторное открытие. Контролирует JS-ошибки и отсутствие запросов скриптов.
  Production-hooks не добавлены. Отдельный тест группировки проверяет один
  шаг истории, порядок слоёв, Undo/Redo и повторное открытие.

## Проверенный результат

Дата: 20 октября 2026 года. Node.js 24.19.0, Playwright 1.64.1,
Debian 13 x64, Chromium 154.0.8037.57 — точная среда PNG-эталонов.

До изменений: source/unit/build прошли; полный браузерный прогон — 36 успешных,
две воспроизведённые known failures, два пропуска ENV-001, неожиданных ошибок нет.
Три точных PNG-эталона прошли и для PWA, и для standalone HTTP (шесть сравнений).
Прототип esbuild на прежнем IIFE прошёл 14 целевых браузерных проверок до миграции.

После изменений: `npm ci`, 206 unit-контрактов, восемь source-проверок,
сборка и `build:verify` прошли. Заключительный полный прогон — **39 успешных
сценариев, две воспроизведённые known failures, два пропуска ENV-001, ноль
неожиданных ошибок** (всего 43 сценария). Все три точных PNG-эталона совпали
в обоих форматах поставки: шесть сравнений. Проверены запуск, документы, текст,
фигуры/изображения, группы/порядок слоёв, история, вкладки, текст по границе,
цвета/градиенты, JSON/PNG, IndexedDB, HTTP standalone, PWA в корне/подкаталоге,
service worker и offline reload. Отдельные новые smoke и группировка также прошли
целевой прогон.

Дополнительное прямое сравнение сохранённого HTML этапа 5 с новой сборкой:
одинаковые UI-действия создали две фигуры, три градиентные точки и группу.
JSON совпал после нормализации только случайных идентификаторов и времени;
состояния после группировки, Undo и Redo совпали. Экспортируемые пиксели совпали
точно; SHA-256 RGBA: `5e205de1c61f2c64e3df8b15aea3fc2703b363ebe2a011a95afe78c2f7fa72bd`.

созданной старой программой, открыт новой: идентификаторы, элементы, группы и
пиксели сохранены без миграции. Ошибок JavaScript не зарегистрировано.
Одноразовый диагностический скрипт/данные находятся в игнорируемом `work/`;
постоянные UI-контракты включены в тесты репозитория.

успешную проверку локального файла; HTTP-прогон её не заменяет. KF-001, KF-002,
KF-003 сохранены. Реальные мобильные устройства, Firefox и Safari не проверялись;
неизменность pointer/touch-кода защищена source-контрактом, это не полный тест жестов.

## GitHub Actions и выпуск

Существующий **Build HTML and PWA** остаётся единственным workflow. Он запускается
для PR в main, push в main с фильтром исходников/инфраструктуры, и вручную.
Порядок: `npm ci` → source → unit → build → verify → штатная установка Chromium
для закреплённого Playwright → один `test:bundle-smoke` на standalone → upload
двух дистрибутивов. В CI не запускается перезапись или пересоздание PNG-эталонов.
Ошибка установки браузера или smoke — настоящая ошибка job; заглушек успеха нет.
GitHub Pages не включается. Серверный результат фиксируется после создания PR.

## Если сборка сломалась / откат

Сначала прочитайте ненулевой результат команды. Выполните `npm ci`, затем
`test:source`, `test:unit`, `build`, `build:verify`. Ошибки отсутствующих файлов,
экспортов, разрешения импортов и маркеров устраняйте в актуальных исходниках.
Не подставляйте исторический `index.html`, не меняйте baseline-хэши и PNG ради
зелёного результата. Если потребуется массовая переделка редактора — остановите
этап, опишите точную несовместимость и вернитесь к небольшой области миграции.
При сетевой блокировке запрашивайте штатное разрешение, сохраняя proxy, TLS и integrity.

Для локальной диагностики прежней сборки создайте отдельную рабочую копию на
`96d8c1ecfc39c9109fb5d5351fa34c6d49949ace`, выполните `npm ci` и `npm run build`.
Не применяйте `reset --hard` к пользовательской рабочей копии. Для отката после
возможного будущего merge подготовьте отдельный revert-PR этапа 6 (для merge-коммита
используется `git revert -m 1 <merge-коммит-этапа-6>`), проверьте исторические
хэши, тесты и выпустите прежние HTML/ZIP вместе. Этот PR автоматически не объединяется.

Следующий этап стоит начать с отдельного аудита зависимостей модели градиентов
и её `uid`/мутаций; переносить её только с сохранением контрактов. Следующий этап
требует отдельного задания.
