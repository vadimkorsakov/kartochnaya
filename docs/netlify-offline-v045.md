# КАРТОЧНАЯ v0.45: Netlify и офлайн-PWA (этап 14А)

## Подключение и публикация

1. В своём аккаунте Netlify выбери **Add new project → Import an existing project → GitHub** и разреши доступ к `vadimkorsakov/kartochnaya`.
2. После проверки и merge этого PR владельцем выбери production branch `main`. До merge можно отдельно проверить ветку PR через Deploy Preview. Этот этап сам сайт не публикует и PR не сливает.
3. Настройки из корневого `netlify.toml`: Node.js **22**, build command `npm run build:netlify`, publish directory **`dist/netlify`**, base directory — корень репозитория. Functions, БД, OAuth и аккаунты пользователей не нужны.
4. В настройках проекта Netlify (Domain management / Production domains) задай свободное постоянное имя, например `имя-проекта.netlify.app`. Используй именно production HTTPS-адрес, а не уникальные адреса деплоев. Не меняй выбранный origin без предварительной ZIP-копии.
5. После подключения GitHub Netlify автоматически собирает новую версию при push в выбранную production-ветку. Проверь успешный deploy и открой постоянный HTTPS-адрес.

`npm run build` создаёт три результата: прежние `dist/kartochnaya.html` и `dist/kartochnaya-pwa.zip`, а также `dist/netlify/`. `npm run build:netlify` создаёт только публикуемый каталог. HTML всегда компилируется из актуального `src/`; исторический HTML и worker не изменяются. Публикуется только `dist/netlify`, содержащий браузерный bundle внутри HTML, manifest, worker, иконки, `tool-icons`, заголовки и воспроизводимый `SHA256SUMS.json`. Исходные модули, тесты, `.git`, документация, конфигурация среды, скачиваемые сборки и пользовательские ZIP в него не копируются.

Netlify отдаёт статические файлы. Проекты, шрифты, ресурсы и настройки остаются в IndexedDB schema v3 браузера. Приложение не отправляет их на Netlify и не выполняет Google-запросы. Сам хостинг видит обычные запросы к статическим файлам.

## Установка и первая подготовка

При первом посещении интернет необходим. Дождись индикатора **«Готово к работе офлайн»**. Он появляется после проверки полного кэша, а не просто после регистрации service worker. Не закрывай страницу во время первой загрузки. При ошибке подготовки подключись к сети и перезагрузи страницу.

- **Android / Chrome:** открой постоянный HTTPS-адрес, дождись подготовки и выбери «Установить приложение» / «Добавить на главный экран» в меню браузера. Формулировка зависит от версии браузера. Запусти приложение с созданной иконки.
- **ПК / Chrome или Edge:** нажми значок установки в адресной строке либо выбери установку приложения в меню. Запусти его через меню приложений ОС.

В браузерах без поддержки установки приложение можно использовать обычной страницей. Для установки не нужны регистрация, Google-аккаунт и авторизация. Проверка мобильного viewport на ПК не является физическим испытанием Android: перед массовым использованием отдельно проверь установку, закрытие и повторный запуск в авиарежиме на настоящем телефоне.

## Проверка офлайн

1. Онлайн дождись готовности, создай документ и внеси правки.
2. Сохрани внешнюю ZIP-копию через раздел «Данные» на главной странице.
3. Отключи Wi-Fi и мобильную передачу данных. Закрой окно PWA и открой установленное приложение снова. На ПК можно также выключить сеть и перезагрузить страницу.
4. Открой сохранённый документ, создай новый, добавь фигуру и текст, дождись автосохранения. Перезапусти приложение и проверь правки.
5. Проверь скачивание и импорт JSON и ZIP без сети. Обычный редактор, пользовательские шрифты, ресурсы и каталог фигур работают локально.

Полная очистка браузером Cache Storage может потребовать новой онлайн-загрузки. Установка сама по себе не гарантирует вечную сохранность хранилища.

## Новая версия и неудачное обновление

Версия кэша зависит от SHA-256 файлов сборки и кода worker. При установке кандидат загружает **все** обязательные файлы и проверяет их SHA-256. Маркер готовности записывается последним. Ошибка HTTP, неполный деплой, несовпадение байтов или нехватка места отменяют установку кандидата; рабочий кэш не удаляется. После успешной активации сохраняются текущий и один предыдущий кэш приложения. В Cache Storage попадают только перечисленные ресурсы приложения; внешние запросы и пользовательские документы туда не записываются.

Браузер ищет новую версию при открытии, возвращении в окно, восстановлении сети и раз в час. Готовый кандидат ожидает: появится **«Доступна новая версия»** и кнопка **«Обновить»**. Страница не перезагружается автоматически посреди работы. Кнопка временно блокирует ввод, завершает текущие операции и через существующий барьер ZIP-снимка подтверждает записи активного и неактивных документов. Только после успеха активируется worker и перезагружается это окно. Другие открытые окна автоматически не перезагружаются.

Если сохранение не подтверждено, обновление откладывается; редактор остаётся открыт. Экспортируй JSON/ZIP, проверь свободное место и повтори позже. При неудачной загрузке новой версии продолжай пользоваться старой офлайн-копией; восстанови сеть и вернись в окно или перезапусти приложение для повторной проверки. **Не очищай данные сайта ради обновления.** Worker не меняет схему v3, не удаляет IndexedDB и не вызывает очистку данных сайта.

## Перенос со старого локального HTML

В прежней актуальной локальной сборке открой «Данные» → «Создать ZIP-копию» → «Всё рабочее пространство». Сохрани ZIP как обычный файл вне хранилища браузера; желательно скопировать его на другой носитель. Открой Netlify-версию и в разделе «Данные» выбери «Восстановить из ZIP». Проверь содержимое и используй добавление копий проектов. Для точной полной замены workspace доступен режим этапа 13: требуется страховочный ZIP текущего состояния, повторный выбор этого файла и подтверждение. Закрой другие окна перед полной заменой. Старые JSON-экспорты также доступны для импорта, но для полного переноса предпочтителен ZIP.

IndexedDB привязана к **origin** (протокол + домен + порт), профилю и браузеру. Локальный HTML, `localhost`, Deploy Preview, постоянный `*.netlify.app` и собственный домен имеют разные хранилища. Смена домена не переносит проекты: сначала экспортируй ZIP на старом адресе, потом импортируй на новом. Два устройства даже с одним Google-аккаунтом не синхронизируют IndexedDB; в этом этапе облачной синхронизации нет. Переноси ZIP вручную.

Очистка данных браузера, удаление профиля, приватный режим и автоматическое освобождение места могут уничтожить локальные проекты. ZIP, сохранённый только внутри данных того же браузера, не является внешней копией. Регулярно сохраняй архивы в обычные файлы вне браузера и проверяй возможность их прочтения.

## Разработчику: проверки и контрольные суммы

Целевые тесты: `npm run test:netlify`. Используется отдельный HTTP-сервер с реальной структурой `dist/netlify` и настоящий Chromium с service worker. Тесты отключают сеть для всего browser context, проверяют повторный запуск, сохранение, экспорт/импорт, успешный и сорванный деплой, отказ сохранения и отсутствие внешних запросов. Chromium CDP проверяет installability; это не физическая проверка Android или системного установщика ПК. Статус KF-003 исторической контрольной сборки не меняется.

Затем: `npm run test:source`, `npm run test:unit`, `npm run build`, `npm run build:verify`, `node scripts/verify-reproducible.mjs` и один полный прогон `npm run test:all`. PNG-эталоны не обновлять. Для Netlify тестов в CI предусмотрен отдельный шаг перед остальными браузерными проверками.

`sha256sum dist/kartochnaya.html dist/kartochnaya-pwa.zip dist/netlify/SHA256SUMS.json` даёт контрольные суммы двух прежних дистрибутивов и манифеста Netlify. Сам `SHA256SUMS.json` перечисляет SHA-256 всех публикуемых файлов, кроме самого себя; порядок детерминирован и не зависит от времени сборки. Его следует сохранить вместе с результатами конкретного проверенного deploy.
