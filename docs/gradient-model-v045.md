## Зависимости, результат и побочные эффекты

| Функция | Вход и результат | Зависимости | Изменение переданного элемента |
| --- | --- | --- | --- |
| `gradientStops(e)` | Элемент → ссылка на его массив остановок | `uid`, `clamp`, `normalizeHex`, Array, Number | Заменяет `e.gradientStops`, если это не массив или длина < 2; иначе сохраняет сам массив и объекты. Записывает `id`, `pos`, `color`, `alpha` каждой остановки; сортирует исходный массив по позиции |
| `gradientGeometry(e)` | Элемент с w/h и углом/координатами → новый объект `{a:{x,y},b:{x,y}}` в локальных пикселях | Number, Math | При отсутствии любой из двух точек заново записывает обе: `e.gradientStart` и `e.gradientEnd`, нормированные относительно размеров. Если обе есть, сохраняет их ссылки и значения |
| `gradientSample(e,pos)` | Элемент, позиция → новый `{color,alpha}` | `gradientStops`, `clamp`, `hexRgb`, `rgbHex`, Math | Косвенно создаёт/нормализует/сортирует остановки через `gradientStops`. Интерполирует RGB с округлением каналов; alpha остаётся дробной |
| `addGradientStop(e,pos=50)` | Элемент, позиция → ссылка на добавленный объект `{id,pos,color,alpha}` | `gradientSample`, `gradientStops`, `uid`, `clamp`, Math | Сначала семплирует исходную позицию, затем генерирует id, округляет ограниченную позицию и alpha, добавляет объект в существующий массив и повторно нормализует/сортирует |

Прямые внутренние зависимости — ровно `uid`, `clamp`, `normalizeHex`, `hexRgb`,
`rgbHex`; зависимость между функциями указана в таблице. `uid` остался в editor
с исходным алгоритмом. `clamp` берётся из primitives, цвета — из colors.
Новые глобальные переменные и runtime import/export не добавлялись.

Порядок внутри `addGradientStop`: `gradientSample` → `gradientStops` → `uid`
новой точки → `gradientStops(...).push` → `gradientStops` → возврат той же точки.
Если остановок ещё нет, сначала генерируются два исходных id, затем третий.
Равные позиции сохраняют стабильный порядок исходных объектов; новая точка
добавляется после существующих с той же позицией.

Функции не обращаются к DOM, app, IndexedDB, истории или Canvas напрямую.
Однако `fillPaint` вызывает geometry/stops при создании CanvasGradient,
а CSS-превью, список точек и оверлей используют те же мутирующие функции.
Расчёт позиции на линии и попадания ручек вызывает geometry; перемещение точки
в pointer-обработчике использует stops, перемещение ручки записывает start/end.
Добавление из кнопки, шкалы или двойного клика вызывает addGradientStop.
Эти потребители, их порядок вызовов, commit/paint/saveSoon не изменялись.

Мутации меняют сам элемент `app.doc`: следующие snapshot, экспорт JSON
и сохранение документа включают нормализованный массив и созданные координаты.
Модель не инициирует сохранение самостоятельно. Извлечение сохраняет этот
существующий контракт, включая изменения при чтении/рендеринге.

## Исторические особенности, сохранённые без исправления

- Единственная существующая остановка отбрасывается вместе с массивом;
  две исходные создаются по fill/fill2 и fillAlpha1/fillAlpha2.
- Отсутствующий/невалидный цвет исходных точек получает #ab92fb/#fb8c67;
  невалидный цвет существующей точки становится #ffffff.
- Числа приводятся через Number и clamp. Невалидная числовая строка даёт NaN,
  null/undefined используют значения по умолчанию, пустая строка становится 0.
  Falsy id заменяется, truthy id сохраняется даже при нестроковом типе.
- Короткий `#ABC` существующей точки становится `#AABBCC` при первом вызове
  stops и `#aabbcc` при следующем: нормализация не полностью идемпотентна.
- null вместо объекта остановки вызывает TypeError после возможных изменений
  предыдущих точек. Транзакционного отката нет.
- Если есть только одна геометрическая точка, обе пересоздаются. Если обе
  существуют, но неполны, пропущенные компоненты дают NaN и не заполняются.
  Невалидный угол/отсутствующий размер также может записать NaN.
- Геометрия использует половину диагонали; концы могут выходить за прямоугольник.
  При нулевых размерах знаменатель ограничивается единицей; возвращаемые
  пиксельные координаты затем умножаются на фактический размер (возможен -0).
  После изменения размеров сохранённые нормированные точки не пересоздаются.
- В совпадающих позициях sample выбирает первый подходящий соседний сегмент.
  Цвет новой точки вычисляется до округления позиции, alpha округляется только
  при добавлении. При дробной позиции цвет может отличаться от цвета,
  вычисленного уже в округлённой позиции.

## Подключение к сборке

Используется прежний `compileJavaScript`, работающий с Buffer. Порядок слотов
соответствует их исходным позициям: primitives → gradient-model → colors.
Относительный порядок primitives/colors сохранён; объявления colors по-прежнему
подняты в том же IIFE и доступны градиентам. Инициализация IIFE не менялась.
Для градиентного слота проверяются hexAlpha, исходная пустая строка, LF маркера
и следующий getGradientStop. Сборка отказывает при отсутствии файла, маркера,
повторении, перемещении, перестановке, неизвестном или неразрешённом маркере.
Новый runtime-модуль, отдельный сборщик и npm-зависимости не вводились.

Временные копии исходников проверяют изменение обоих дистрибутивов при правке
нового фрагмента и отказ сборки при его удалении. Повторные полные сборки
и отдельные цели html/pwa дают одинаковые байты. Восстановленный JavaScript
сравнивается целиком с историческим. Каждая из четырёх функций объявлена один раз.

от app/DOM, сохранения и pointer-обработчиков. Возможное выделение чистых

мутаций, генерации id и нормализации. Зафиксированные здесь исторические
особенности нельзя незаметно менять под видом извлечения. Следующий этап
в этом задании не начинался.
