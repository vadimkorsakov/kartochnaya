База: `cf46ab4bfac39dcbe98bde518cc32701d42016d1`, актуальная main после merge PR #39.

## Подтверждённый дефект

`task()` в `src/backup/ui.mjs` обрабатывал одинаково отказ проверки входного ZIP,
чтения текущего workspace, подготовки и записи. После ошибки он вызывал
`replacement.cancel()`, затем `releaseArchive()`, удалял DOM и предлагал выбрать ZIP заново.

Первое сравнение выполняет `snapshot()` **после** успешного `readBackup()`.
`replacement.prepare()` также читает текущую базу, но уже под эксклюзивной блокировкой.
Отказ этих чтений не опровергает целостность исходного ZIP. Повторное сравнение
после переключения режима и отказ Web Locks из-за второго окна теряли тот же архив.

Первый коммит `d778cff` содержит только тесты и исходное свидетельство
[restore-lifecycle-f08-baseline.json](restore-lifecycle-f08-baseline.json).
На неизменённом production-коде: четыре локальных сценария и два cloud retry
падают на отсутствии `#zipReplacePrepare`. Для локальных случаев перед этим
проверены неизменность всех четырёх stores и отсутствие дополнительных readwrite.
Для всех шести проверено отсутствие эксклюзивных блокировок.
Восемь существующих контрольных сценариев проходят уже на базе: запрет без prepare,
повреждённый ZIP, rollback, частичный отказ localStorage и optional safety download.

В собственной новой локальной постановке пустой входной workspace заменён
на workspace с документом: иначе после успешного восстановления запускается
штатное создание стартового примера. Четыре воспроизведения повторно запущены
с итоговым fixture на исходной базе в detached worktree. В собственном новом
Yandex generation-тесте используется реальный submit настройки Client ID:
Яндекс не подписывается на `storage`-событие этого ключа. Исходные существующие
тесты и их assertions не изменены; в двух cloud spec добавлены только новые тесты.

## Состояния и право подтверждения

| Состояние | Поля/владение | Доступные действия |
| --- | --- | --- |
| Выбран, не проверен | `busy`, owner; `verified` отсутствует | Ожидание `readBackup`; подтверждение выключено |
| Проверен | `verified`, `restoreBytes`, действующий owner | Копии проектов либо выбор полной замены |
| Сравнение/подготовка | `busy`; подтверждение выключено | Свежий snapshot/barrier, затем штатный prepare |
| Подготовлен | `prepared`, session ready и контрольный снимок | Optional safety ZIP и финальное подтверждение |
| Подготовка отказала | `prepared = false`; ZIP и owner сохранены | Явная повторная подготовка или отмена |
| Источник недействителен | `releaseArchive`, удалён restore view | Только новый выбор и проверка ZIP |
| Запись запрошена | `verified = null`, `prepared = false` | Штатный commit; повторный клик не запускает запись |
| Запись завершена | session committed либо отказ с release | Перезагрузка при успехе; новый выбор после отказа |

Большая новая state machine не вводится. В `task()` только сравнение и подготовка
явно передают callback `retryPreparation`. Он используется лишь при наличии
`verified` и `restoreBytes`, действующей capability и отсутствии commit.

После отказа сначала отменяется session и освобождаются её временный снимок,
seal и эксклюзивная блокировка. Затем owner проверяется повторно: освобождение
может быть асинхронным. Старое сравнение очищается, ready скрывается, confirm
остаётся disabled, prepare становится доступным. Сообщение сохраняет причину
и объясняет, что ZIP остался в памяти и требуется новая подготовка.

`SecurityError`/`NotAllowedError` не допускают сохранения доверенного источника.
Отзыв capability, abort сигнала, смена Google/Yandex generation или истечение
сеанса также ведут к прежнему release. Проверка входного ZIP и операции записи
не имеют права на `retryPreparation`: повреждение, SHA mismatch и неуспешный commit
не превращаются в retry с прежним подтверждением.

Проверка owner выполняется перед/после асинхронных чтений и optional safety packaging.
Само необязательное скачивание по-прежнему может отказать без потери действующего
контрольного снимка. При недействительном owner этот optional-контракт не применяется.

## Сохранённые защиты и ресурсы

`replace.mjs`, `archive.mjs`, IndexedDB v3, Web Locks, workspace barrier, sticky
`writeFailure`, проверка ревизий документов, сравнение текущих записей внутри
readwrite-транзакции и ожидание transaction complete не изменены.
Любой retry снова проходит исходный `replacement.prepare()`; никакого очистителя
`writeFailure`, запасного snapshot или обхода instance guard нет.

`commit()` повторно проверяет ZIP, owner, preferences и базу под транзакционной
блокировкой. После запроса записи архив не удерживается для preflight retry.
Отказ после подтверждённого commit сохраняет сообщение о подтверждённой IndexedDB
и необходимости ручной перезагрузки. Он не объявляет прежнюю базу неизменной
и не запускает восстановительную запись.

Остаются один исходный Uint8Array и существующая разобранная модель; новых
полноразмерных копий и постоянного ZIP-кэша нет. OAuth-токены не сохраняются.
Cancel, Escape, крестик, новый ZIP и отзыв owner освобождают архив по прежнему
контракту. Переключение вкладки сбрасывает подготовку; возврат требует prepare.
Закрытие очищает сохранённые views; новое открытие не возвращает старый архив.

## Регрессии

Новые 16 local browser и 6 cloud browser проверяют:

- Первое/повторное сравнение, prepare, readonly abort и отказ Web Locks → retry того же ZIP.
- Disabled confirm, освобождение locks, новое чтение и изменившееся число settings.
- Удержанный настоящий docs.put: retry ждёт последнюю ревизию и transaction complete;
  safety ZIP содержит именно подтверждённый документ.
- Успешное восстановление после retry: ровно одна replacement-транзакция,
  transaction complete, точные записи всех stores и повторная проверка после reload.
- Sticky writeFailure, отказ доступа и drift после повторного prepare.
- Неверный SHA, отмена/крестик/Escape, мобильная геометрия и возврат между режимами.
- Ошибка после commit: база действительно заменена, ручной reload, без ложного rollback.
- Google/Yandex: один download, retry без загрузки заново, disconnect и смена generation.

Старые browser-регрессии дополнительно проверяют CRC/недоверенные источники,
истечение capability, abort реальной записи, несколько окон и desktop/mobile размеры.
Целевые unit: **85 passed**. Полный регресс и CI приведены в описании PR.

## Границы

Retry выполняется по явному нажатию. Устойчивый отказ хранилища, неподтверждённая
запись и отсутствующие Web Locks продолжают блокировать prepare. Проверенный ZIP
живёт только до закрытия/перезагрузки диалога и только при действующем owner.
Права облака после передачи проверяются существующей локальной capability;
дополнительных сетевых запросов авторизации нет. Ошибки после запроса записи
не входят в preflight retry. Старые версии приложения не участвуют в Web Locks.
F-06/F-09, схема БД, лимиты памяти, форматы и импорт проектов вне изменения.
