# Диапазонный интерлиньяж горизонтального текста (#114)

`textRuns[].style.lineHeight` — положительный конечный числовой множитель.
Отсутствие override наследует значение слоя; невалидный override отбрасывается,
сохраняя остальные свойства диапазона. Невалидное базовое значение при рендеринге
заменяется на 1.15. Схема IndexedDB v3 не меняется.

Для каждой визуальной строки общий layout вычисляет:

- `A = max(ascent фрагментов)`, `D = max(descent фрагментов)`;
- `R = max(fontSize фрагмента × его lineHeight)`;
- `H = max(R, A + D)`;
- `baseline = y + A + (H - A - D) / 2`, следующая строка начинается в `y + H`.

Размеры здесь эффективные, после существующего масштабирования mixed fontSize.
Автоподбор использует этот же layout и сохраняет множители интерлиньяжа.
Он может изменить fontSize и вследствие этого переносы. При выключенном
автоподборе изменение только lineHeight не меняет горизонтальную геометрию.
Однородные существующие документы сохраняют прежнюю формулу высоты/baseline.

Интерлиньяж исключён из ключей глифов и shaping. Максимальная требуемая высота
переносится при объединении исходных фрагментов и токенов. При побуквенном
разбиении слишком длинного токена учитываются исходные значения его графем,
а не максимум всего слова. Границы внутри составной графемы подчиняются
существующему правилу первого символа, как fontSize и декорации.

LF не увеличивает высоту непустой строки: её определяют печатаемые фрагменты,
включая пробелы. Пустая строка берёт lineHeight своего LF, последняя пустая
строка после завершающего LF — lineHeight этого LF. Шрифт и его метрики пустой
строки остаются базовыми, как в существующих документах с mixed fontSize;
override размера/семейства только на LF не меняет геометрию пустых строк.
Полностью пустой слой берёт базовый стиль. Для пустых строк DOM получает
те же метрики шрифта и baseline. U/S на пустой
строке не рисуются. Все строки позиционируются общим layout, CSS их не переносит.

Поле инспектора показывает эффективное значение диапазона/каретки либо всего
слоя вне редактирования, с `Mixed` при различиях. При непустом выделении ввод
и стрелки форматируют только выбранные символы. Первый шаг из Mixed использует
значение первого символа диапазона, в том числе при обратном выделении;
без выделения — базовое значение слоя.
Выделение сохраняется в UTF-16 с направлением, а поле удерживает фокус при вводе.

Без выделения сохранена прежняя семантика: изменение пишет базовый lineHeight
слоя, существующие явные диапазонные override сохраняются. Это не стиль будущего
ввода. Поэтому значение под кареткой внутри явного override может отличаться
от изменённого базового значения. В специальных режимах (vertical/path/boundary,
arc/justify) интерлиньяж остаётся свойством слоя, как прежде. Существующие
ограничения доступности WYSIWYG по эффектам/трансформациям не расширяются.

Целевые unit-тесты находятся в `rich-text.test.mjs` и `rich-text-layout.test.mjs`.
`selected-text-line-height.spec.js` проверяет реальные поля и Selection,
автоподбор ON/OFF, Undo/Redo/Escape, повторное открытие и IndexedDB/reload,
русский абзац с soft-wrap, LF/пустые строки, смешанные шрифты/размеры/трекинг/U/S.
Геометрия измеряется в DOM независимым baseline-маркером и Range, сравнивается
с фактическими Canvas-вызовами и скачанным PNG. PNG дополнительно сверяется
с растром, восстановленным по измеренным DOM-координатам (1px для сглаживания,
при отдельной проверке координат с точностью 0.12px). Существующие PNG-эталоны
не обновляются. Спецификация включена и в оба Firefox-проекта (PWA/Netlify).
