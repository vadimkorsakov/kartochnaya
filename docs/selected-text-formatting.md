# Форматирование выделения в textarea

Горизонтальный текст использует существующие desktop/mobile инструменты шрифта,
начертания, размера, цвета и трекинга. Непустой диапазон textarea передаётся в
`applyTextStyle()`; без выделения сохраняется изменение всего слоя. Нормализация,
пересечения, удаление базовых переопределений и границы UTF-16 остаются в модели.
Вертикальный текст, текст по кривой, boundary, дуга и justify сохраняют свой путь.

`selectionStart`, `selectionEnd`, `selectionDirection` сохраняются до передачи
фокуса инструментам, а также при select/selectionchange/keyup/input/pointerup. Панели могут
получить обычный фокус, включая числовую клавиатуру Android, не завершая сессию.
Кнопки инструментов сохраняют фокус textarea и нативную подсветку. Поля и select
получают штатный фокус; выбор шрифта/цвета кнопкой и Enter в числовом поле
возвращают фокус textarea с прежним диапазоном. Пока пользователь вводит значение
в другом поле, подсветку определяет браузер; CSS-имитация не используется.
Повторный вход через «Править» возвращает фокус и выделение. Новых элементов UI нет.

Размер выбранных символов переводится из текущих пикселей в опорные единицы:
`requested * textRunsBaseFontSize / fontSize`. Если опорного размера ещё нет,
используется текущий размер слоя; затем вызывается существующий
`retainRichTextSizeBase()`. Ручной размер отключает автоподбор, как поле размера
всего слоя: остальные фрагменты сохраняют и исходные размеры, и текущий масштаб.
Последующее включение автоподбора снова масштабирует все фрагменты пропорционально.
Остальные метрические изменения используют существующий пересчёт раскладки.

Изолированная история `inline-text-history.mjs` хранит снимки слоя и курсора
только в памяти сессии. До первого форматирования браузер управляет обычным undo
ввода, включая сгруппированные операции. После форматирования Ctrl/Cmd+Z,
Ctrl/Cmd+Shift+Z, Ctrl+Y, beforeinput historyUndo/historyRedo и существующие кнопки
истории восстанавливают текст вместе со стилями. Input-preview и финальный change
одного инструмента дают один снимок; новая правка после Undo отсекает Redo.
При завершении снимки передаются в существующую историю документа, без отдельного
повторного коммита закрытия. Сессии без форматирования сохраняют прежнее правило
одного коммита. Desktop Escape восстанавливает весь исходный слой, включая опорный
размер и флаг автоподбора; мобильная «Готово» сохраняет текущую сессию.

Textarea временно показывает базовый стиль. Смешанные стили видны в Canvas после
завершения ввода и в PNG; WYSIWYG остаётся отдельной задачей. CSS имитации смешанных
стилей не добавлены. Схемы JSON/ZIP/IndexedDB и документы без textRuns не меняются.

Браузерные сценарии: `tests/selected-text-formatting.spec.js`, вместе с существующими
`rich-text`, `rich-text-rendering`, `inline-text` и `mobile-inline-text`. Проверки
используют настоящие UI-события, наблюдают вызовы Canvas без подмены рисования,
проверяют пиксели экрана/PNG и повторное открытие из IndexedDB. Мобильный Chromium
эмулирует touch/viewport; аппаратная клавиатура и системные Android handles требуют
проверки на устройстве.


## Диагностика взаимодействий после проверки Deploy Preview

Исходный HEAD `8fdcb00` проверен через реальные клики в Chromium 154 и Firefox 157,
включая Netlify-сборку. Изменение `textRuns` и итоговый Canvas/PNG работали.
Пользователь уточнил, что оформление всё-таки применяется, но его не видно до
завершения ввода, а подсветка исчезает при обращении к свойствам. Первый эффект —
согласованное ограничение textarea, оно сохранено до WYSIWYG.

Воспроизведённая регрессия desktop: кнопки шрифта/цвета получали обычный фокус на
mousedown. Сессия и диапазон `[0,6]` сохранялись, но браузер скрывал нативную
подсветку неактивной textarea. Четыре проверки фокуса (два инструмента × два
браузера) упали на старом HEAD и прошли с исправлением. Теперь mousedown кнопок
существующих инструментов сохраняет фокус textarea. На input/select это правило
не распространяется. После выбора из поиска/пересоздания инспектора восстанавливаются
фокус, начало/конец и направление диапазона.

Числовой Enter раньше переводил фокус на Canvas на desktop, а на телефоне оставлял
его на body. Отдельная touch-проверка упала до исправления; сейчас Enter возвращает
редактирование текста, если сессия активна. Обычная работа с числовыми свойствами
слоя вне текстовой сессии не меняется.

Дополнительная защита: `rememberInlineCaret()` читает DOM-диапазон только пока
фокус принадлежит textarea. События select/selectionchange от неактивного контрола
и панелей не могут затереть сохранённый диапазон. Добавлен document.selectionchange
для системного выделения. Контрактный Android event replay после настоящего
двойного touch-касания и фокусировки поля воспроизводит поздние события select и
selectionchange с уже схлопнутым DOM-диапазоном: старый HEAD менял размер всего слоя,
новая версия сохраняет диапазон и форматирует только слово. Это воспроизведение
последовательности событий, а не подтверждение такого поведения физического Android.

Зависимость inlineToolPointer от `setTimeout(...,0)` заменена явным владельцем
перехода к инструментам до следующего pointerdown. Гонка таймера не объявляется
первопричиной: наблюдаемый desktop-сбой происходил из-за передачи фокуса кнопке.

Новые регрессии: selected-text-interaction.spec.js и selected-text-touch.spec.js.
Они используют двойной щелчок, Shift+стрелки, реальные mouse/touch-клики по меню и
элементам, поиск шрифта, обычный ввод числа и Enter. Перед/после открытия меню
сравнивается снимок настоящей нативной подсветки без визуальных эталонов; проверяются
textRuns, фокус, продолжение ввода, Undo/Redo, Escape, реальные вызовы Canvas и
пиксели/изменение PNG. Тесты не восстанавливают фокус через .focus() перед проверкой.

Ограниченный Firefox-набор для HTML/PWA и Netlify:
`npm run build && npm run build:netlify && npx playwright install firefox && npm run test:selection:firefox`.
Он также добавлен в GitHub Actions. Полный test:all остаётся Chromium-набором.
Нативные Android handles, Gboard/другие IME и видимость системной подсветки на
физическом телефоне остаются непроверенными; touch-эмуляция не заменяет эту проверку.
