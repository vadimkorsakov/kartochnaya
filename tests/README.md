# Базовые проверки v0.45 — этап 0

Редактор не изменён. Здесь находятся только инструменты разработки, синтетические
данные и эталоны. Нет новой сборки приложения, генерации ZIP или миграции исходников.

## Установка и запуск

Команды выполняются в корне репозитория, не внутри `kartochnaya v0.45/`.
Проверенная версия Node.js — 24.19.0 (также записана в `.node-version`).
Тестовая инфраструктура требует Node.js >=22. Версии devDependencies и транзитивных
зависимостей закреплены `package.json` и `package-lock.json`.

```sh
npm ci
```

Для текущей облачной среды используйте установленный браузер:

```sh
export PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium
npm test
npm run test:known
npm run test:all
npm run test:visual
```

Это соответственно основные проверки, отдельные known failures, весь набор и
только сравнение PNG. В PowerShell переменная задаётся через
`$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = "путь-к-браузеру"`.

`npm test` не скачивает браузер и не обновляет эталоны. Для обычной установки
браузера Playwright вне текущего окружения предусмотрено:

```sh
npm run test:install
```

Этот скрипт устанавливает Chromium, соответствующий Playwright 1.64.1, в игнорируемый
`.cache/ms-playwright/` (либо в заданный PLAYWRIGHT_BROWSERS_PATH). Установка зависит
от доступа к официальному CDN; здесь он заблокирован с `403 Domain forbidden`.
Другой браузер не подставляется незаметно: для системного нужен явный executablePath.

**Версия загружаемого Playwright-браузера отличается от браузера текущих эталонов.**
Зафиксированные эталоны созданы на Linux x64, Debian 13, Chromium 154.0.8037.57
(пакет `154.0.8037.57-1~deb13u1`). Для их сравнения нужен именно этот браузер;
все данные находятся в [baselines/environment.json](baselines/environment.json).
Проверка окружения отклоняет другой Chromium до сравнения PNG. Она не создаёт
ложный визуальный diff и не перезаписывает эталоны. На другом браузере можно отдельно
проверить невизуальные сценарии, явно исключив визуальную группу:

```sh
npm test -- --grep-invert 'visual baseline'
```

Это ограниченный прогон, не полный результат визуального сравнения. Для переносимых
визуальных прогонов нужно воспроизвести записанную среду либо отдельно согласовать
новую среду/набор эталонов; нельзя заменять существующие PNG ради зелёного результата.

На Linux могут понадобиться системные библиотеки Chromium. Их отсутствие должно
устраняться установкой штатных зависимостей браузера, а не ослаблением проверок TLS
или изменением редактора. Скрипт не устанавливает системные пакеты от root.

## Сервер и изоляция

Playwright сам запускает `scripts/test-server.mjs` на 127.0.0.1:4173 и завершает его
после прогона. Node.js-сервер отдаёт исходные файлы без инъекций и преобразований.
Занятый порт — ошибка: чужой сервер не переиспользуется. Для ручной диагностики
есть `npm run test:serve`; перед автоматическим прогоном его надо остановить.

Каждый тест получает новый browser context и собственную IndexedDB. Тесты не
открывают пользовательский профиль, не меняют существующие проекты и не записывают
данные напрямую в app/IndexedDB. Создание и изменение объектов идут через UI,
импорт — через штатный file input, наблюдение модели — через штатный JSON-экспорт
и readonly-транзакции. Нет test hooks во внутренний `app`, init script или патча HTML.

Автоматический наблюдатель проверяет pageerror и console.error с начала навигации
до конца сценария. Исключение — ровно 404 необязательного, не подключённого
`/favicon.ico`, который Chromium запрашивает самостоятельно.

Для ручной диагностики HTML-отчёт находится в `playwright-report/`, JSON-результат —
в `test-results/results.json`. При ошибках сохраняются screenshot и trace.
Все эти файлы игнорируются Git. Пароли, личные данные и внешний контент не используются.

## Состав и интерпретация

| Файл | Назначение |
| --- | --- |
| `baseline.spec.js` | Все 19 файлов релиза, SHA-256/размеры, характеристики HTML |
| `smoke.spec.js` | Старт/схема БД, новый документ, текст, фигура, фото, Undo/Redo, reload, PNG |
| `distribution.spec.js` | Ресурсы PWA, одиночный HTML через file://, офлайн-service-worker |
| `visual.spec.js` | Три точных PNG-сравнения в зафиксированном окружении |
| `known-failures.spec.js` | KF-001: ссылки документа; KF-002: папки ресурсов |
| `helpers.js` | UI-действия, экспорт, чтение сохранённых записей и проверка ошибок |

В `known-failures` используется Playwright `test.fail`, а не skip. Setup должен
завершиться до установки метки. Ожидается падение конкретной проверки правильного
контракта. Неожиданный успех потребует снять метку и зарегистрировать исправление.
Основной набор `npm test` не включает этот проект. `npm run test:all` запускает оба.

Стандартный итог Playwright включает expected failures в "passed". Дополнительная
строка `Baseline summary` разделяет реально прошедшие, воспроизведённые known failures,
пропуски и неожиданные результаты. JSON-отчёт содержит фактический и ожидаемый статусы.

## Проверка одиночного файла и ограничение облачного браузера

Тест копирует **только** исходный HTML во временную пустую папку, отключает сеть,
открывает его через file://, создаёт документ/фигуру и проверяет PNG. Он также
проверяет отсутствие HTTP-запросов. Копия и загрузки находятся в test-results,
исходный релиз не меняется.

В текущем управляемом Chromium навигация блокируется административной URL-политикой.
Тест отмечается как **skipped ENV-001**, с диагностическим attachment. Это не pass
и не подтверждение работоспособности file://. Автоматизация не отключает политику.
Для строгого приёмочного прогона в окружении, где file:// разрешён:

```sh
KARTOCHNAYA_REQUIRE_FILE_URL=1 npm run test:all
```

В строгом режиме административная блокировка приводит к ненулевому коду выхода.
Доступность файлов PWA и работа service worker не равнозначны устанавливаемости PWA:
отсутствие подключения manifest остаётся KF-003.

## Визуальные эталоны

В Git сохраняются PNG полного экспорта холста 320×240:

- `blank-320x240.png` — белый пустой холст;
- `shapes-320x240.png` — прямоугольники, поворот и полупрозрачный круг;
- `text-320x240.png` — две строки кириллицы/латиницы в DejaVu Sans 27 px.

Используются экспортируемые пиксели документа, а не масштабируемый editor canvas,
размер которого зависит от viewport. Сравнение декодированных пикселей точное;
сжатые байты PNG не объявляются визуальным контрактом. В эталоны не попадают
время, UUID, системные панели, рамки выделения и пользовательские данные.

Шрифт поставляется только как fixture: `fixtures/fonts/DejaVuSans.ttf`, SHA-256 и
лицензия сохранены. Текстовый тест импортирует его штатным механизмом и проверяет
реальный загруженный FontFace. В приложение шрифт автоматически не добавляется.
Исходный файл взят из Debian-пакета `fonts-dejavu-core 2.37-8`; сохранён его copyright.

`updateSnapshots: 'none'` не позволяет обычному прогону создавать или обновлять PNG.
`npm run test:visual:record` предназначен только для первичного формирования эталонов
при их полном отсутствии и отказывается работать, если уже существует хотя бы один
PNG. В этой ветке эталоны уже созданы; повторно запускать запись не нужно.

При несовпадении сначала изучают trace, actual/diff и характеристики среды. Не надо
передавать `--update-snapshots`, удалять PNG или снимать проверку шрифта для прохождения
тестов. Изменение эталонов — отдельная ручная работа с объяснением причины и review.

## Контрольная точка и границы

См. [исходное состояние](../docs/baseline-v045.md), [контрольный манифест](../docs/baseline-v045.json)
и [реестр известных проблем](../docs/known-issues.md).

Набор можно использовать как начальную защиту при последующем разделении монолита:
он наблюдает приложение снаружи и не требует конкретного устройства JS-модулей.
Хэш-проверка намеренно защищает исходный релиз этапа 0; на этапе изменения поставки
её политику нужно пересмотреть отдельно, сохранив исходную контрольную точку.

Этот набор не даёт полного покрытия Canvas, эффектов, масок, вложенных групп, серий,
мобильных жестов, экранной клавиатуры и отказных режимов хранилища. Реальные Android,
Firefox и iOS в этом этапе не проверялись. Следующий этап миграции не начат.
