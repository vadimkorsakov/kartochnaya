# Google Drive: ручные ZIP-копии, v0.45, этап 14В

Облачная карточка доступна в Netlify-сборке. Обычные HTML и PWA ZIP,
исторические дистрибутивы, формат ZIP, IndexedDB v3, автосохранение и алгоритм
service worker не меняются. Подключение через GIS Token Model и scope
`https://www.googleapis.com/auth/drive.file` остаётся прежним.

## Создать копию

1. Открой «Данные → Google Drive» и подключи подтверждённый аккаунт.
2. Нажми **Создать облачную копию**. Барьер редактора подтверждает сохранения
   активной и неактивных вкладок, затем читает согласованный снимок четырёх
   хранилищ IndexedDB. Блокировка снимается до упаковки и сетевой передачи.
3. Существующий `createBackup` упаковывает всё рабочее пространство: проекты,
   документы, встроенные ресурсы, шрифты, settings и разрешённые настройки.
   Проверяются контейнер и полный scope; вычисляется SHA-256 итогового ZIP.
4. Приложение ищет обычную видимую папку **КАРТОЧНАЯ — резервные копии** с
   MIME `application/vnd.google-apps.folder`, `trashed = false` и маркерами
   `appProperties.application = kartochnaya-v045`, `kind = backup-folder`.
   Совпадения только по имени недостаточно. Чужие одноимённые папки не используются.
   Поиск учитывает все страницы. При нескольких допустимых папках выбирается
   первая по дате создания. До первого явного создания копии папка не создаётся.
5. Папка переиспользуется, причём её metadata проверяется повторно. Если известная
   папка удалена или недоступна, операция завершается диагностикой. Кнопка
   **Создать новую папку при следующей загрузке** разрешает повторный поиск и
   последующее создание по нажатию **Создать облачную копию**. Файлы не переносятся.
6. Каждый ZIP получает существующее имя с датой и UUID и отдельный Drive file ID.
   Нет PATCH, перезаписи, удаления и очистки старых архивов. Metadata содержит
   маркер приложения, kind, backupId, format, scope и SHA-256. Содержимое проектов,
   списки ресурсов и персональные данные в metadata не записываются.
7. Успех показывается только после завершения upload с 200/201, нового ID и
   отдельного GET metadata с совпадением ID, размера, родительской папки,
   имени и всех ожидаемых свойств. Затем вручную обнови список.

## Передача и разрывы

Создание resumable-сеанса выполняется единственным POST на
`https://www.googleapis.com/upload/drive/v3/files?uploadType=resumable`.
Адрес из Location проверяется до добавления Authorization: HTTPS, точный origin
`https://www.googleapis.com`, точный upload path, uploadType=resumable и upload_id.
Произвольные адреса, HTTP, credentials, fragment и URL с access_token отклоняются.
Все запросы используют Bearer header, omit credentials, no-store и redirect:error.

Части по 8 МиБ — представления `subarray` исходного ZIP, без копирования всего
архива на каждую часть. 308 обрабатывается по подтверждённому Range с проверкой
границ и монотонности. Основной прогресс «Загрузка: … / … МБ» показывает байты,
подтверждённые Drive; дополнительный счётчик показывает границу отправляемой части,
а не измеренный сетевой трафик (Fetch не сообщает upload-progress).

После сетевой ошибки, 429/5xx или непрочитанного финального JSON приложение
проверяет тот же сеанс PUT с `Content-Range: bytes */TOTAL`. Только подтверждённая
позиция определяет следующую часть. Проверки ограничены тремя попытками с короткой
задержкой; отсутствие прогресса также ограничено. 403 показывает запрет доступа,
401 сбрасывает авторизацию. Каждый HTTP-запрос и чтение тела ограничены 60 секундами.
Неопределённый результат не считается успехом: обнови список перед новой копией.
Новый upload того же ZIP автоматически не запускается.

Отмена, отключение, уход офлайн, смена Client ID и истечение доступа прерывают
соответствующие запросы. Уже завершившийся серверный архив может остаться в Drive:
проверь список. Незавершённый сеанс не удаляется приложением. Resumable URL живёт
только в памяти, не записывается в журналы и постоянные хранилища. После закрытия
вкладки возобновления нет. Локальная база не меняется при облачных сбоях.

## Список, скачивание и восстановление

**Обновить список** вручную читает файлы из проверенной папки: `trashed = false`,
ZIP MIME и appProperties приложения. Используются нужные fields, pageSize=100,
nextPageToken, сортировка от новых к старым. Ответ повторно фильтруется по маркерам,
папке и полному scope. Для защиты от повреждённой пагинации установлен предел
100 страниц. Имена и metadata отображаются через textContent.

**Скачать** повторно проверяет папку и metadata выбранного ID перед GET alt=media.
Размер проверяется до выделения буфера, Content-Length — при наличии. Поток
читается в один заранее ограниченный Uint8Array; лишние/недостающие байты запрещены.
Проверяются SHA-256 всего ZIP, если он присутствует в metadata, и существующий
`readBackup`: контейнер, манифест, CRC, SHA-256 вложений, связи и количества.
Дата, объём, число проектов и предупреждения показываются перед отдельной кнопкой
**Сохранить ZIP на устройстве**. Имя очищается от путей, управляющих и опасных
символов; браузеру передаются исходные проверенные байты. Сообщение о передаче
браузеру не гарантирует, что пользователь подтвердил сохранение.

Скачивание и просмотр не записывают данные в IndexedDB. Для восстановления
выбери сохранённый файл в **Локальные ZIP-копии → Восстановить из ZIP**, проверь
предпросмотр и отдельно подтверди существующий режим восстановления.

## Память и автономность

Облачное скачивание ограничено 256 МиБ ZIP, на Android — 128 МиБ. Бюджет проверки
распакованных данных остаётся существующим (512 МиБ), поэтому для большого ZIP
потребуется существенно больше RAM, чем размер файла. Эти пределы не гарантируют
наличие памяти: JSON, декодированные записи и внутренние буферы браузера также
занимают RAM. При отказе выделения показывается понятная ошибка; освободи память
или используй компьютер. Uint8Array скачивания не копируется в промежуточный
полноразмерный массив; Blob создаётся только при явном сохранении. Сам readBackup
сохраняет существующую модель памяти, потокового восстановления нет.

Нет фонового polling, автоматической синхронизации, расписания и автоматического
восстановления. После перезагрузки требуется действие пользователя для нового
подключения: access token, аккаунт и resumable-сеанс живут только в замыкании/памяти.
Токен не передаётся UI, не хранится в DOM, базе, localStorage, sessionStorage или ZIP.
Сохраняется только публичный Client ID. GIS загружается по явному действию.

Файлы в Drive содержат исходные данные ZIP **без дополнительного шифрования
КАРТОЧНОЙ**. Защита аккаунта и доступ к папке определяются Google Drive. При отсутствии
сети локальное редактирование, автосохранение и локальные ZIP остаются доступны.
Netlify HUD/Powered by Netlify: автоматическая вставка стороннего скрипта должна
оставаться отключённой в настройках хостинга.

## Проверки

- `npm run test:drive`: OAuth и mock Drive API, реальные ZIP и chunk buffers,
  папки/маркеры, 308/200/201, запрос позиции после потери части/финального ответа,
  HTTP-ошибки, неправильный Range, metadata, пагинация, размер, hash/ZIP и отмена.
- Один сценарий с ZIP на 40 МиБ проверяет размер частей и общую backing memory.
- `npm run test:netlify`: прежние OAuth/PWA-проверки плюс сквозное создание двух
  облачных ZIP, безопасный список, точные скачанные байты и локальное восстановление;
  повреждение ZIP не включает сохранение; редактор работает во время удержанной
  сетевой передачи, отключение её завершает, локальный ZIP работает офлайн.
- Финальные source/unit/PWA, build verification/reproducibility, браузерный регресс
  и GitHub Actions обязательны. Исторические release-файлы проверяются по SHA-256.

## Ручное испытание настоящего Drive на production

После отдельного одобрения и слияния PR/деплоя открой
https://kartochnaya.netlify.app (либо preview PR с разрешённым OAuth origin).
Проверить этот новый код на production до деплоя нельзя.

1. Дождись готовности офлайн-кэша. Создай проект с несколькими документами,
   изображением и пользовательским шрифтом; сохрани локальный страховочный ZIP.
2. В «Данные» подключи уже проверенный Google Client ID/аккаунт. Убедись, что
   папка ещё не создавалась от одного подключения или обновления пустого списка.
3. Создай облачную копию. Во время загрузки открой документ и внеси ещё одно
   изменение: оно должно сохраняться локально, но не менять уже полученный снимок.
4. Дождись подтверждения успеха, обнови список и проверь обычную видимую папку
   и ZIP в веб-интерфейсе Drive. Повтори: должны появиться два разных файла.
5. Скачай один файл через КАРТОЧНУЮ. Проверь дату, размер, число проектов,
   сохрани ZIP и открой его через существующий локальный интерфейс восстановления.
   Добавь копии проектов; сравни документы, ресурсы и шрифты.
6. Для большого архива один раз прерви сеть во время передачи. Не ожидай ложного
   успеха. После явного переподключения обнови список прежде, чем создавать новую
   копию. Не ожидай сохранения upload-сеанса после reload.
7. Отдельно проверь отмену и отключение, истечение доступа, удалённую папку и
   явное создание новой. КАРТОЧНАЯ сама не удаляет и не переносит файлы.
8. Перейди офлайн: редактирование, автосохранение и локальные ZIP должны работать.

Реальный upload/download нового кода требует пользовательского Google-аккаунта;
mock-тесты подтверждают протокол и данные, но не заменяют эту ручную проверку.
