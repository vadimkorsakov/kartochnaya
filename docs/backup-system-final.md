# Резервные копии КАРТОЧНОЙ

IndexedDB v3 остаётся основным хранилищем редактора. ZIP содержит проекты,
документы, ресурсы, пользовательские шрифты, settings и известные настройки
приложения. Облачные Client ID, реестры аккаунтов и OAuth-токены в ZIP не входят.

## Сохранить ZIP на устройстве

Открой «Резервные копии» → «Создать резервные копии». Сними флажки облаков и
нажми «Подготовить и отправить». Дождись подтверждения сохранений IndexedDB,
создания и проверки архива. Нажми **«Сохранить ZIP на устройство»** и проверь
фактическую загрузку в браузере. Передача файла браузеру ещё не доказывает, что
он записан на диск. Локальный сценарий работает без сети и подключённых облаков,
в автономном HTML и PWA.

Самостоятельное окно «Локальные ZIP-копии» также позволяет создавать полный ZIP
или несколько выборочных ZIP с выбранными проектами. Если ресурсов или шрифтов
слишком много, уменьши их объём либо используй выборочные копии.

## Один ZIP в несколько облаков

Сначала подключи нужные аккаунты в самостоятельных окнах Google Drive и
Яндекс Диска. В едином окне подключённые доступные получатели отмечены изначально;
лишние флажки можно снять. Google поддерживает несколько аккаунтов, Яндекс — один.
На телефоне списки получателей и результатов разбиты на страницы.

Операция резервирует выбранных получателей, один раз вызывает согласованный
снимок `zipSavedSnapshot()`, один раз `createBackup()` и проверяет результат
`readBackup()`. Проверяются workspace scope, формат, backupId, имя, состав,
manifest, размеры, CRC и внутренние SHA-256. SHA-256 всего ZIP вычисляется один
раз. Сетевые клиенты получают один объект, один Uint8Array, filename, manifest и
backupId. Между отправками workspace не читается и не сериализуется заново.
Google использует свой прежний resumable upload; Яндекс — прежнюю двухэтапную
загрузку без overwrite. Отправки последовательны.

Перед первой отправкой проверяется размер для всего выбранного набора:
Google — 256 МиБ; Яндекс — 256 МиБ на компьютере и 128 МиБ на Android. Если хотя
бы один предел превышен, не начинается ни одна загрузка. Сохрани подготовленный
ZIP локально, заверши сценарий и исключи несовместимое направление либо уменьши
архив. Самостоятельный локальный ZIP сохраняет существующий бюджет формата:
512 МиБ распакованных данных плюс ограниченный служебный объём.

Каждый получатель имеет свой статус и подтверждение. Итог «Подтверждено N из M»
не означает успех остальных направлений. Google проверяет server metadata,
appProperties, имя, размер и заявленный SHA-256; Яндекс — имя, тип, размер и
серверный SHA-256 при его наличии. При отсутствии серверного SHA-256 Яндекс явно
сообщает, что подтверждены имя и размер. Это не серверная побайтовая проверка.

Кнопка локального сохранения передаёт браузеру те же байты, которые отправлялись
в облака. ZIP остаётся в памяти до завершения/закрытия сценария. При закрытии
активная передача отменяется, завершение отмены освобождает резервирования и
буфер. Уже подтверждённые файлы не удаляются. Новый запуск создаёт новый backupId.

## Подключение Google и Яндекса

В Google Drive настрой публичный Web application Client ID, добавь Google-аккаунт,
подготовь авторизацию и отдельным нажатием подключись через Google. Для каждого
аккаунта подтверждается устойчивый ID. Используется только `drive.file`.

В окне Яндекса настрой публичный Client ID и точный Redirect URI, показанный
приложением. Нажми «Подключить Яндекс», разреши popup и заверши OAuth с PKCE.
Доступ ограничен `cloud_api:disk.app_folder`, операции идут только через `app:/`.
Папка приложения подтверждается API. Как в самостоятельном клиенте, известный
ID аккаунта перепроверяется; если `/info` изначально недоступен, принадлежность
ограничивается тем же поколением единственного OAuth-сеанса. Старый ID не
подставляется, а потеря ранее известного ID требует повторного подключения.

Токены находятся только в памяти. После перезагрузки или истечения доступа
подключись повторно явным действием. Локальные проекты и ZIP доступны независимо.
Изменение OAuth scope и автоматическое расширение разрешений не выполняются.

## Скачать облачную копию

В окне Google выбери аккаунт, открой список копий и нажми «Скачать». В окне
Яндекса открой «Облачные копии» → «Обновить список копий» → «Проверить и скачать».
Клиент ограниченно скачивает архив, проверяет его и показывает сводку. Затем
можно сохранить ZIP на устройство или перейти к восстановлению прямо в КАРТОЧНОЙ.
Все три самостоятельных окна продолжают работать отдельно от пакетной операции.

## Добавить копии проектов

В локальном ZIP-окне выбери архив либо передай проверенный архив из облака.
После проверки выбери «Добавить копии проектов» и подтверди. Существующие проекты
и документы сохраняются; копии получают новые внешние ID, недостающие начертания
шрифтов добавляются. Settings и известные настройки не заменяются. Повторный
импорт добавляет ещё копии.

## Полностью заменить workspace и сделать страховочную копию

Открой проверенный полный workspace ZIP, выбери «Заменить рабочее пространство»,
прочитай сравнение и предупреждения. Закрой остальные окна КАРТОЧНОЙ и нажми
«Подготовить замену». Действующие Web Locks, контрольный снимок и запрет
редактирования остаются обязательными. Выборочный ZIP для замены не подходит.

До окончательного подтверждения скачай страховочный ZIP текущего workspace и
проверь его наличие в загрузках. Контрольный снимок в памяти не заменяет файл
страховочной копии после успешной замены. Отмена освобождает подготовленную
операцию без замены данных. При подтверждении IndexedDB заменяется одной
транзакцией; при отказе транзакции действует rollback. Настройки localStorage
применяются после commit и могут потребовать отдельной проверки.

Пакетный запуск запрещён, пока локальный ZIP-диалог владеет восстановлением или
подготовленной заменой. Модальные окна не накладываются. Резервирование облаков
не очищает переданный restore lease; локальное завершение освобождает его.
`restore()` и `replacement.commit()` остаются единственными путями записи.

## Неподтверждённая загрузка и истёкший сеанс

Если результат PUT Яндекса неизвестен, ZIP **мог сохраниться**. Открой список
копий нужного аккаунта и проверь файл по имени и backupId перед повтором.
Автоматический повтор того же объекта ZIP запрещён. После отмены активного PUT
также возможен сохранённый файл; сообщение не обещает отсутствие последствий.
Подтверждённые копии других получателей остаются на месте.

Google также сообщает о неподтверждённом исходе. Его существующее восстановление
resumable-сессии сохраняется, но координатор не повторяет загрузку целиком.
Если сеанс отключился во время подготовки, соответствующая отправка не начинается.
Новый OAuth-сеанс не подставляется вместо выбранного. Подключись явно, проверь
списки и запусти новый сценарий с новым ZIP/backupId.

## Проверить сохранность архива

Проверь фактическое наличие локального файла, его размер и имя. Открой ZIP через
«Восстановить копию» для проверки CRC, SHA-256, manifest и связей; само открытие
не изменяет документы. Скачанную из облака копию можно проверить тем же способом.
Для независимого сравнения файлов сравни SHA-256 целого ZIP внешней утилитой.
Храни хотя бы одну копию вне устройства и периодически проверяй её чтение.

## Ограничения

- Нет автоматической синхронизации, фоновых загрузок или расписания.
- Нет дополнительного шифрования ZIP: защити доступ к файлам и аккаунтам.
- Облака, сеть, OAuth и квоты могут быть недоступны.
- Закрытие приложения прерывает операцию; фонового продолжения нет.
- Локальная копия остаётся независимым способом восстановления.
- Успешный API-ответ не гарантирует вечную сохранность облачного файла.
- Реальные OAuth и особенности браузера проверяются живым сценарием; browser-тесты
  используют контролируемые ответы провайдеров.

## Живая проверка Firefox

1. Открой доверенный HTTPS preview PR, подключи два Google-аккаунта и Яндекс.
2. Создай тестовый документ, сохрани его. Выбери все три направления в едином окне.
3. Дождись трёх отдельных подтверждений, сохрани этот ZIP на устройство.
4. В самостоятельных окнах обнови списки, скачай каждый созданный файл; сравни
   имена, backupId и SHA-256 целых ZIP с локальным файлом.
5. Проверь открытие каждого ZIP в локальном окне без подтверждения восстановления.
6. Повтори с одним Google, одним Яндексом, без облаков и без сети для локального ZIP.
7. Отмени передачу: проверь независимые результаты и списки, не повторяй неизвестный
   PUT вслепую. Истёкший сеанс подключи явным действием.
8. На тестовых данных проверь добавление проектов, страховочный ZIP и отмену
   подготовленной полной замены. Пока замена подготовлена, пакетное окно не открывается.
