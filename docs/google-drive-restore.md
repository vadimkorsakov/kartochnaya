# Google Drive: прямое восстановление ZIP (15В-3)

Один публичный OAuth Web application Client ID обслуживает несколько Google-аккаунтов.
Каждая запись реестра имеет отдельный OAuth-сеанс и клиент Drive. Access tokens
остаются в памяти; публичное состояние сеанса содержит только поколение авторизации
и срок действия, необходимые для проверки актуальности, без токена.

После скачивания клиент проверяет папку приложения, размер, доступный серверный
SHA-256, внутренние хеши, manifest, workspace scope и backupId. В «Облачных копиях»
показаны имя, размер, дата архива, число проектов, результат проверки и предупреждения.
Можно сохранить ZIP на устройство или нажать «Восстановить в КАРТОЧНОЙ».
Передача браузеру не гарантирует фактическое сохранение: проверь загрузки браузера.
Сохранение оставляет проверенный ZIP доступным; Object URL освобождается штатным
30-секундным таймером, без досрочного отзыва при переходе к восстановлению.

Передача в `backupUI.openArchive(bytes, { signal, check, opener })` происходит
после события закрытия Google-диалога и возврата фокуса. Новый GET к Drive не нужен.
Uint8Array передаётся без дополнительной полной копии; локальный диалог повторяет
`readBackup()` и по умолчанию выбирает «Добавить копии проектов».

Lease проверяет запись аккаунта в реестре по идентичности объекта, экземпляр
OAuth-сеанса, подтверждённый accountId, поколение авторизации, срок действия и
идентичность выбранного результата скачивания. Проверки продолжаются после передачи,
включая проверку перед транзакцией добавления и перед записью полной замены.
Повторная авторизация той же записи отзывает старый lease уже при её начале.
Отключение, удаление, новый OAuth-сеанс, потеря доступа, истечение токена и смена
Client ID также отзывают lease. AbortSignal вызывает штатную отмену локального
восстановления, освобождая подготовленный снимок и Web Locks. Причина показана
на карточке Google Drive после закрытия диалога.

При переключении аккаунта прежний ZIP освобождается. Поздний результат скачивания
не может стать архивом нового аккаунта. В Google Drive хранится не больше одного
активного проверенного ZIP. После передачи байтами владеет локальный диалог;
Google сохраняет только lease без буфера. Локальный диалог освобождает данные
после завершения, отмены или ошибки. ZIP не сохраняется в постоянном хранилище
браузера и не переживает reload.

Добавление использует существующие `restore()` / `importProjectSet()` и атомарную
транзакцию с переназначением внешних ID. Существующие проекты сохраняются.
Полная замена использует прежние prepare, страховочный ZIP, отдельный финальный
confirm, повторную проверку ZIP и lease, атомарную замену IndexedDB, rollback и reload.
Формат ZIP, IndexedDB v3, scope `drive.file`, resumable upload и GIS не меняются.
Сохранённый на устройство локальный ZIP независим от Google: его можно открыть
обычным локальным диалогом без OAuth и сети.

Память: одновременно нужны сжатый ZIP, распакованные данные и структуры проверки;
при полной замене дополнительно удерживается контрольный снимок текущей базы,
при скачивании страховочного ZIP — ещё упакованный снимок. Blob при сохранении
также может потребовать дополнительной памяти. Большие архивы лучше восстанавливать
на компьютере. Существующие лимиты скачивания: 256 МиБ, на Android — 128 МиБ.
Реальные OAuth popup и доступ к Google зависят от настроек Google Cloud; автоматические
тесты используют подменённые ответы GIS/Drive и настоящие IndexedDB/Web Locks браузера.

**ZIP не шифруется дополнительно приложением. Облачное восстановление не является автоматической синхронизацией.**
