## Модель аккаунтов

`src/cloud/google-drive/accounts.mjs` управляет записями без ограничения количества.
Каждая запись имеет provider `google-drive`, подтверждённый Google Drive
`about.user.permissionId`, отображаемое имя, отдельные OAuth-сессию и Drive-клиент,
кэш папки, AbortController текущей операции, результат и проверенный скачанный ZIP.
ID проверяется до публикации сеанса как подключённого. Документация Google:
https://developers.google.com/workspace/drive/api/reference/rest/v3/about#User

Реестр `kartochnaya-cloud-accounts-v1` в localStorage содержит только
`provider`, `id`, `name`, `clientId`. Существующий ключ
`kartochnaya-google-drive-client-id` остаётся источником общего публичного Client ID.
Старый сеанс без сохранённого Google ID нельзя восстановить: интерфейс предлагает
повторно добавить аккаунт. После reload все сохранённые записи требуют подключения
по действию пользователя. Подготовка GIS и синхронный вызов popup разделены.
Одно OAuth-приложение обслуживает все аккаунты; scope остаётся `drive.file`.
Токены находятся только в замыканиях сессий, не передаются менеджеру или DOM.

Для повторного подключения создаётся временная сессия с ожидаемым ID. Выбор чужого
аккаунта отклоняется, исходная запись и рабочий сеанс сохраняются. Повторное
добавление известного ID сохраняет существующую сессию. Удаление из списка
отменяет операции только этой записи; API удаления файлов не добавлен.

При выборе нескольких аккаунтов менеджер резервирует получателей, один раз
вызывает существующий `zipSavedSnapshot` (барьер локальных сохранений и
согласованный снимок IDB), `createBackup`, `readBackup` и SHA-256 полного ZIP.
Приватный WeakMap отмечает подготовленный архив; клиенты используют один digest
и одинаковые байты. Загрузка последовательная. Каждая копия подтверждается
metadata, включая папку, маркеры приложения и SHA-256. Ошибка одного получателя
не отменяет остальные копии. Ссылка менеджера на большой ZIP освобождается
в finally. Автоматического повтора нового upload нет.

`archive.mjs`, формат ZIP, schema IndexedDB v3, редактор, механизм полной замены
workspace, PNG-эталоны и исходные исторические HTML/PWA-файлы не изменены.
Как и на этапе 14В, облачный интерфейс подключён только при сборке Netlify;
исторические standalone HTML/PWA ZIP остаются побайтово прежними.

## Изменённые файлы

- `src/cloud/google-drive/accounts.mjs`: реестр, сессии, операции, общая копия.
- `src/cloud/google-drive/session.mjs`: permissionId и защита повторной авторизации.
- `src/cloud/google-drive/client.mjs`: однократная подготовка проверенного ZIP.
- `src/cloud/google-drive/ui.mjs`: компактный список, выбор получателей, результаты.
- `tests/google-drive-accounts.test.mjs`: семь сценариев менеджера, покрывающих
  разные аккаунты, дубликаты, токены, папки/списки/скачивание, три одинаковые
  загрузки, частичную ошибку, удаление, reload, Client ID и чужую идентичность.
- `tests/google-drive.test.mjs`, `tests/google-drive-backup.test.mjs`: ответы Google
  теперь содержат устойчивый permissionId.
- `tests/google-drive.spec.js`: обновлённый интерфейс и браузерный сценарий на
  ширине 390 px, локальный ZIP и редактирование offline, запрет токенов в хранилищах
  и облачного реестра/Client ID в ZIP.
- `package.json`, `.github/workflows/build.yml`: целевые проверки до регресса.
- `docs/google-drive-accounts-v045.md`: этот отчёт.

## Проверка на настоящих аккаунтах

1. Открыть HTTPS preview ветки PR. Разрешить его точный origin в настройках
   существующего Web OAuth Client ID; включить Drive API, при testing добавить
   оба Google-аккаунта в test users. Отдельные OAuth-приложения не нужны.
2. В «JSON и копии → Облачные хранилища → Google Drive» проверить сохранённый
   Client ID. Добавить Google A: подготовить авторизацию, затем открыть Google
   явной кнопкой. Повторить для Google B. Обе строки должны быть подключены.
3. Попытаться добавить A ещё раз: третья строка не появляется, B остаётся подключён.
4. Создать локальный проект. Отметить A и B, создать копию в выбранных аккаунтах.
   Дождаться отдельного подтверждения каждой загрузки. В каждом Drive должна
   появиться собственная папка приложения с ZIP с одинаковым именем и backupId.
5. Поочерёдно открыть «Просмотр копий» A и B, скачать ZIP, дождаться проверки
   SHA-256, сохранить на устройстве. Сравнить SHA-256 двух скачанных файлов:
   байты должны совпасть. Локальные проекты при скачивании не меняются.
6. Перезагрузить: оба имени остаются, оба требуют подключения, Google popup
   автоматически не открывается. В строке A начать подключение и выбрать B:
   показать ошибку, исходная строка A не меняется. Затем подключить правильно.
7. Удалить A из списка. Его строка исчезает, ZIP на Google Drive A остаётся,
   подключение и операции B продолжают работать. Добавление A снова разрешено.
8. Дополнительно с A/B/C: вызвать ошибку загрузки B (например, запрет/квота);
   проверить подтверждения A и C и отдельную ошибку B. Перед повторной загрузкой
   B проверить список, поскольку неподтверждённый файл мог уже сохраниться.
9. На Android включить offline: создать/редактировать документ, сохранить
   локальный ZIP. Вернуть сеть: облако требует явного подключения, локальные данные
   сохраняются. Проверить удобство строк и отсутствие горизонтального скролла.

## Ограничения

Реальная интерактивная авторизация двух личных Google-аккаунтов в этой среде
не выполнялась; автоматические тесты используют GIS/Drive mocks. Сценарий выше
нужно выполнить на разрешённом HTTPS origin перед выпуском.

После reload токены не восстанавливаются и не обновляются в фоне. Истечение
сеанса, offline и закрытие страницы прерывают операции. Квоты Drive и ограничения
доступа зависят от аккаунта. ZIP может остаться в Drive после разрыва связи;
нужно проверить список перед отдельным повтором. Скачивание на Android сохраняет
существующий бюджет 128 МиБ, на остальных устройствах — 256 МиБ; создание ZIP
сохраняет существующее ограничение 512 МиБ распакованных данных.

## Автоматическая валидация

Порядок CI: `test:drive` → `test:source` → `test:unit` → `test:pwa` → build,
`build:verify`, независимая воспроизводимость → `test:netlify` → один полный
`test:all`. Итоговые числа, Actions run, проверенный SHA и контрольные суммы
дистрибутивов приведены в описании PR #19, чтобы отчёт ссылался на финальный
коммит без самоссылочного изменения его SHA.

Локально выполнены проверки синтаксиса и тест OAuth-сессии. Полный локальный
прогон заблокирован отсутствующими в offline npm-кэше fflate/esbuild/fake-indexeddb;
проверки сборки и браузера выполняются в GitHub Actions через обычный `npm ci`
с неизменённым package-lock.json. Сеть среды и proxy не перенастраивались.
