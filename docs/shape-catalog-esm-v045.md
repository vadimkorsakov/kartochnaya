## Фактический контракт

Вход — массив категорий `{name, shapes}`. Выход — новый массив категорий
`{name, shapes}`, содержащий новые объекты фигур. Порядок категорий и фигур
сохраняется, неизвестные поля отбрасываются. Синтетический JSON не мутируется;
повторные вызовы дают одинаковые независимые вложенные объекты и матрицы.

| Поле / структура | Историческое правило |
| --- | --- |
| Категории | Не более 300; иначе `Некорректный каталог фигур` |
| Название категории | `String(g.name\|\|'').trim().slice(0,100)`; пустое — `Группа без названия` |
| Повторные названия | Разрешены, включая совпадения после trim/обрезания |
| `shapes` | Не-массив заменяется `[]`; берутся первые 1500 элементов |
| `id` | `String(s.id\|\|'').slice(0,100)`; пробелы сохраняются; пустые и повторные ID запрещены во всём каталоге, после приведения и обрезания |
| `d` фигуры | `String(s.d\|\|'').slice(0,160000)`; проверяется уже обрезанная строка |
| `name` фигуры | `String(s.name\|\|'Фигура').slice(0,100)`, без trim |
| `mode`, `lineStyle`, `capStart`, `capEnd` | Только при truthy-входе: `String(...).slice(0,20)`, без проверки перечисления значений |
| `outlineCaps` | При значении, отличном от null/undefined, записывается `!!value`; иначе поле отсутствует |
| `parts` | Только массив; первые 500 частей. Пустой массив сохраняется, не-массив не создаёт поле |
| `parts[].d` | `String(part.d\|\|'')`; пустое, длина >160000 или запрещённые символы — `Неверный SVG path` |
| `parts[].matrix` | Массив преобразуется через `.map(Number)`; не-массив заменяется `[1,0,0,1,0,0]` |
| Компоненты матрицы | Ровно 6; конечные числа, модуль ≤10000000 включительно; округления нет. Ошибка: `Неверное SVG преобразование` |

Порядок создаваемых полей фигуры: `id`, `name`, `d`, затем присутствующие
`mode`, `lineStyle`, `capStart`, `capEnd`, `outlineCaps`, `parts`.
В категории — `name`, `shapes`, в части — `d`, `matrix`.

Оба вида path проверяются тем же выражением:

```js
/^[\s\d.eE+\-,MmZzLlHhVvCcSsQqTtAa]+$/
```

Оно допускает перечисленные команды обоих регистров, цифры, точки,
экспоненциальные `e/E`, знаки, запятые и пробельные символы. Это фильтр символов,
а не SVG-парсер: например, строка из пробелов или `eE.,+-` принимается.
Неизвестная команда отклоняется. Ошибка ID/основного path:
`Некорректный контур: ` плюс уже обрезанный ID.

Проверка верхнего уровня предшествует категориям; проверка имени категории —
фигурам; ID/основной path — частям; path части — матрице этой части.
`null` вместо категории, фигуры или части может вызвать штатный `TypeError`.
Единая дополнительная проверка структур намеренно не добавлена.

## Потребители и граф модулей

Единственный прямой потребитель — `applyShapeCatalog(data)`. Он сначала получает
полностью проверенный новый каталог и только затем заменяет `SHAPE_SECTIONS` и
перестраивает индекс. При ошибке валидатора прежний каталог остаётся на месте.

Цепочки вызовов:

- `loadShapeCatalog()` → `applyShapeCatalog()` → `validateShapeCatalog()`;
- `importJSON()` → `applyShapeCatalog()` → `validateShapeCatalog()`;
- `importProjectBackup()` / `importWorkspaceBackup()` → `applyShapeCatalog()` → валидатор.

`importJSON()` исторически применяет и сохраняет `shapeCatalog` до проверки
остального файла и до передачи проектному/рабочему импортеру. Этот порядок и
возможное повторное применение каталога сохранены.

Новый граф содержит ребро `editor.js` → `core/shape-catalog.mjs`.
Новый модуль — лист без импортов и внешнего состояния. Он не зависит от DOM,
Canvas, `app`, `uid`, `window`, IndexedDB или библиотек; циклов не добавляет.
Метаданные esbuild проверяются source-тестом. Модуль включён в единственный
классический IIFE, функция не раскрывается через `window`.

esbuild остаётся **0.28.2**, параметры сборки не менялись. Runtime-зависимостей,
CDN, внешних JavaScript-файлов или новых npm-зависимостей нет.

## Намеренно сохранённые недостатки

Фильтр path не гарантирует синтаксическую корректность SVG. Повторные категории,
потеря хвостов длинных массивов и основного пути, свободные значения метаданных,
truthiness-преобразование строк (`outlineCaps: 'false'` → `true`), возможные
`TypeError` и раннее применение каталога до остальных проверок импорта —
историческое поведение. Усиление этих правил требует отдельной задачи и оценки
совместимости. KF-001/KF-002/KF-003 не исправлялись; ограничения ENV-001 сохранены.

## Откат и следующий шаг

До merge достаточно закрыть PR. После merge — отдельный revert итогового коммита
этапа 8, затем `npm ci`, unit/source, build/verify и browser smoke. Возврат функции
в `editor.js` не требует миграции или удаления IndexedDB/пользовательских каталогов.

Кандидат следующего небольшого этапа — отдельный аудит чистых преобразований
геометрии для поиска одной самостоятельной функции без DOM/`app` и её последующего
выделения с историческими контрактами. SVG-парсер и импортеры требуют отдельной
оценки; этап 9 здесь не начат.
