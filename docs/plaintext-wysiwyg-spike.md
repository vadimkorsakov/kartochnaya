# PR #66: plaintext-only feasibility spike — Gate 0 не пройден

Дата: 31 октября 2026. База: `bc90ed49fd04198b3c0d5a8a9ca974955d8305c3`
после PR #65. Изучено приложенное архитектурное заключение.

`contenteditable="plaintext-only"` со стилизованными `span` пригоден для
дальнейших экспериментов с нативным вводом, но его текущая раскладка существенно
расходится с Canvas. Desktop WYSIWYG **не интегрирован**. `src/editor.js`, textarea
на ПК/мобильных и в специальных режимах, модель сохранения, IndexedDB и PNG-эталоны
не изменены. Постоянного второго представления текста нет.

## Измерения в браузерах

Проверены Chromium **154.0.8037.57** и Playwright Firefox **157.0**, Linux Debian 13,
zoom=1, DPR=1. Встроенный тестовый DejaVu Sans (`SpikeSans`) и системный `monospace`;
размеры 20/32/40 px. Использованы существующие `richTextSpans()`,
`resolveRichTextStyle()` и `createRichTextLayoutEngine()`.

Для каждой графемы записываются UTF-16 start/end, фактическая строка и DOM Range
rect, collapsed Range до/после графемы, Canvas X начала/конца и baseline.
DOM Range top сравнивается с Canvas baseline минус font bounding ascent.
Это сравнение прямоугольников/метрик; прямой API baseline у DOM Range отсутствует.
Строки группируются по baseline, выведенному из Range top и font ascent, включая
hard breaks и пустые строки. Пересечение glyph rect непригодно: при небольшом
lineHeight прямоугольники соседних строк перекрываются. Данные не извлекаются из внешнего вида отдельных слов.

| Сценарий | Chromium: max ΔX / ΔY, px | Firefox: max ΔX / ΔY, px | Переносы |
| --- | ---: | ---: | --- |
| Обычный кириллический текст | 0,014 / 1 | <0,001 / 0,5 | совпали |
| `AA`20 + `BB`40 + `CC`20, ширина 65 | 0,553 / 0 | 0,550 / 3 | совпали |
| Два семейства и размера | 0,014 / 3,406 | <0,001 / 3 | совпали |
| Длинное слово через границу стиля | 1,141 / 4,609 | 1,150 / 4,100 | совпали |
| Три пробела у переноса | 0,014 / 4 | <0,001 / 3,5 | совпали |
| **Пять пробелов у переноса** | **74,502 / 25** | **74,483 / 24,5** | **разошлись** |
| `A😀👩‍💻Б é` | 0,017 / 1 | <0,001 / 0,6 | совпали |
| Center / right | ≤0,026 / 1 | <0,001 / 0,5 | совпали |
| `A\n\nБ\n` | 0 / 2 | 0 / 3 | совпали, включая пустые строки |

Воспроизводитель: `alpha     beta gamma`, width=75, fontSize=20,
lineHeight=1.15, первые шесть UTF-16 единиц красные. DOM первая строка `[0,10)`,
Canvas `[0,8)`; две последние позиции пробелов остаются в DOM на предыдущей строке.
CSS `white-space:pre-wrap` допускает висящие пробелы. Canvas сохраняет пробелы,
разбивая переполнение по графемам. Поиск произвольного CSS-смещения это не исправит.

Максимальное расхождение collapsed caret после учёта affinity: Chromium
**74,504 / 25 px**, Firefox **68,650 / 24,5 px**. Даже при совпадении переносов
вертикальное расхождение достигает 4,609 px (Chromium) и 4,100 px (Firefox).
CSS line boxes при lineHeight=1.15 расходятся с минимумом Canvas ascent+descent.
В span явно задан тот же unitless lineHeight: font shorthand иначе сбрасывает его
в normal и скрывает эту разницу. Collapsed rect присутствовал у всех
измеренных позиций. На soft-wrap один UTF-16 offset имеет две допустимые визуальные
позиции: выбирается ближайшая из Canvas-позиций соседей. Исходные rect сохраняются
в диагностике, без этой интерпретации они дают ложные ошибки на границе строки.

`npm run test:spike` сохраняет полные измерения и `gatePassed` как JSON attachments
в `test-results/spike-results.json`. Успех диагностических тестов **не означает**
успешный Gate 0: в обоих браузерах `gatePassed=false`. CI публикует отдельный
артефакт `plaintext-spike-measurements` до очистки результатов общим Playwright.

## Нативные действия и курсор

По семь сценариев в каждом браузере: реальные клики, двойной клик по слову,
Shift+стрелки, ввод, Enter, повторные пустые строки, Backspace, Delete,
составные emoji/ZWJ, вставка форматированного HTML через реальные Ctrl+C/Ctrl+V
как обычного текста. Проверены обратное/прямое выделение, границы span, все
UTF-16 offsets строки с emoji и пустыми строками, преобразование element-point,
восстановление логического диапазона после изменения размера span.

Клики по видимой букве проверены при 50/100/200% и повороте 0/30°. Эти проверки
относятся к изолированному host, а не к геометрии панели/Canvas приложения.
Middle/bottom verticalAlign, hit-test в RTL и сложное shaping ещё требуют
самостоятельных проверок после согласования переносов.

После Home → Backspace на второй пустой строке текст в обоих браузерах одинаков:
`Привет мир\nZ`. Но следующий End даёт Chromium offset **12**, Firefox offset **10**:
Firefox сохраняет визуальную привязку к предыдущей строке после merge. Снимок
`native-end.json` фиксирует это до Ctrl+End; браузерное различие не исправляется
программной подстановкой Selection. Для последующего удаления используется
явный Ctrl+End, и канонический текст проверяется вновь.

Прототип `surface.mjs` хранится только в `tests/spikes`. Это ограниченный mapper
Text/span/BR, с явным отказом при неизвестных block-узлах. Его BR-sentinel правила
проверены только на фактически полученном DOM этих браузеров. Он не является
универсальным HTML serializer или готовым production-адаптером. DOM строится через
Text/textContent, без вставки пользовательского HTML. Повторное полное построение
индекса в тестовом mapper не переносится в paint или production keypress.

## IME и beforeinput

`compositionstart` блокирует перестроение host; `compositionupdate` и
некэнселируемые `beforeinput`/`input` не пересоздают composing subtree.
После `compositionend` вызывающая сторона читает актуальный текст и только затем
обновляет проекцию. Отложенный старый текст не применяется автоматически.

Проверка синтетическая: она доказывает guard/контракт события, но не поведение
системной IME. Реальные IME, Gboard, undo-группировка композиции и интеграция
`updateText`/`replaceText` с `inline-text-history.mjs` не заявлены проверенными.
При будущей интеграции необходимо согласовывать итог через `input`, независимо
от отменяемости `beforeinput`, и завершать композицию одной операцией истории.

## Логические границы движка

Единственное изменение production-кода — дополнительные неперсистентные поля:

- Строка: `[start,end)`, `nextStart`, `softWrap` в UTF-16 исходного `element.text`.
- Hard break принадлежит `[end,nextStart)`; LF занимает одну единицу, CRLF — две.
- Soft wrap: `end === nextStart === следующая.start`, `softWrap=true`.
- Последняя строка: `nextStart === text.length`, `softWrap=false`.
- Пустая строка имеет `start===end`, включая последнюю после trailing LF.
- Фрагмент: `[start,end)` покрывает исходный текст, не разрезая графемы.
  Legacy одиночный CR игнорируется при рисовании, но сохраняет логический offset;
  поэтому срез source для такого фрагмента может включать игнорируемый CR.

X/Y/width/height/baseline, алгоритм переносов и частота измерений не меняются.
Временная проверка старого и нового engine дала **225 точных совпадений** всей
прежней геометрии/текста: пять строк × пять ширин × три горизонтальных × три
вертикальных выравнивания. Сохранён unit-тест инвариантов LF/CRLF/CR, Unicode,
пустых строк и soft wraps. Покомпонентная карта caret при каждом paint не строится.

## Следующая самостоятельная задача

Согласовать переносы и caret-affinity DOM/Canvas до интеграции desktop WYSIWYG.
Начать с приведённого воспроизводителя пяти пробелов. Сравнить общий алгоритм
переносов и вариант явно заданных границ строк; для последнего проверить нативные
стрелки, мышь, copy/paste через виртуальные разрывы, отсутствие лишних LF в модели.
Не изменять экспортную геометрию или PNG-эталоны как обход проблемы.

Критерии: одинаковые UTF-16 границы всех строк/пустых строк в обоих браузерах,
caret ΔX/ΔY ≤2 CSS px при zoom=1, mixed fonts/sizes и пробелы; затем zoom/rotate,
middle/bottom, реальные IME и взаимодействия инструментов PR #65. Только после
этого — подключение истории, форматирования и сохранения (Gate 2–4).

## Выполненная проверка

До создания PR: 14 spike-тестов passed (7 Chromium + 7 Firefox), 30 существующих
Chromium-проверок passed (selected-text interaction/touch, rich rendering, PNG),
10 Firefox interaction-проверок passed (HTML/PWA и Netlify), unit-файлы
rich-text-layout/rich-text/inline-text-history, test:source, build, build:netlify,
build:verify и git diff --check passed. PNG-эталоны не обновлялись.

Firefox в облачном контейнере требует `XDG_CONFIG_HOME`/`XDG_CACHE_HOME` внутри
`work/` и `MOZ_DISABLE_CONTENT_SANDBOX=1` из-за read-only `/proc/self/uid_map`.
Это локальная настройка запуска, не изменение приложения или конфигурации CI.
Полный CI запускается после создания PR; его результат указывается в PR отдельно.

Повторение на обычной Linux-среде:

```sh
npm ci
PLAYWRIGHT_BROWSERS_PATH="$PWD/.cache/ms-playwright" npx playwright install chromium firefox
npm run test:spike
```

Если Chromium уже предоставлен средой, установить только Firefox и передать
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`; скачивать второй Chromium не требуется.
Spikes используют отдельный сервер на 4175 и не требуют сборки приложения.
