# Gate 0B/2: terminal LF и нативный ввод

База: удалённый `main` bf86e64, merge PR #69; 904e54d является его предком.
Изолированный spike, Chromium 154.0.8037.57 и Firefox 157.0, SpikeSans 20px,
`break-spaces` + font-metrics line-height 24px. Редактор и сохранение не изменены.

## Результат

**Chromium Gate 0B/2 FAIL:** sentinel исправляет проверенный ввод пустых строк,
но `A → Enter` немедленно читается как `A\n\n` вместо `A\n`.
**Firefox: PASS ограниченного smoke** (21/21 подслучай), без объявления строгих
Gate 0A/0B пройденными. Chromium: 20/21; успешное выполнение диагностики
с воспроизводителем блокера не означает безопасное сохранение.

Текст ниже записан с экранированными LF. Координаты — левый верх Range новой `Z`
относительно host, px; Canvas ожидает те же координаты. Offset — UTF-16, selection
схлопнута. Результаты клика и восстановления через offset совпадают; Ctrl+End
проверен отдельно для каждой последней строки, на свежих mount.

| Действие | Chromium: точный текст / offset / Z (x,y) | Firefox: точный текст / offset / Z (x,y) |
| --- | --- | --- |
| `A\n\nБ`, средняя строка, Z | `A\nZ\nБ` / 3 / (0,24) | `A\nZ\nБ` / 3 / (0,24) |
| `A\n`, последняя строка, Z | `A\nZ` / 3 / (0,24) | `A\nZ` / 3 / (0,24) |
| `A\n\nБ\n`, последняя строка, Z | `A\n\nБ\nZ` / 6 / (0,72) | `A\n\nБ\nZ` / 6 / (0,72) |
| `\n\n`, средняя строка, Z | `\nZ\n` / 2 / (0,24) | `\nZ\n` / 2 / (0,24) |
| `\n\n`, последняя строка, Z | `\n\nZ` / 3 / (0,48) | `\n\nZ` / 3 / (0,48) |
| `A`, Enter, сразу после input | **`A\n\n` / 2** / нет Z | `A\n` / 2 / нет Z |
| Затем Z (после предыдущей проверки) | `A\nZ` / 3 / (0,24) | `A\nZ` / 3 / (0,24) |

Контроль без sentinel с той же геометрией: клик в последнюю строку `A\n`, Z
даёт **`AZ\n`, offset 2 в обоих браузерах**, а не `A\nZ`.

## DOM-маркер и affinity

`spike.mount(value,{terminalBr:true})` добавляет `<br data-caret-sentinel>` только
при терминальном LF, непосредственным ребёнком host после span. По умолчанию
режим выключен; исходные 24 диагностических случая и прежние native-тесты
сохранены. BR не добавляет текст или UTF-16 единицы; `index()` явно игнорирует
маркер, `applyMetricLineHeight()` обходит только host и прямые span.
Проверены все offsets в обеих affinities и все границы дочерних узлов host.
Отдельно `A😀\n` с последним диапазоном 40px: surrogate offsets сохранены,
BR наследует 20px host, индексы метрик соответствуют двум span.

Для финального offset upstream возвращает конец текстового узла, downstream —
позицию host непосредственно перед BR. Обе позиции отдельно устанавливаются
в Selection, переводятся в offset, проходят remount и восстановление; последующая
нативная Z попадает на правильную последнюю строку. Восстанавливается выбранная
политика downstream для финальной пустой строки, а не произвольная прежняя affinity.
В Chromium collapsed Range обеих конечных позиций по-прежнему не имеет rect;
успешный ввод не доказывает строгую геометрию пустого caret.

Range новой буквы измерен **до** пересоздания DOM. Только после этого отдельный
mount ожидаемой канонической строки синхронизирует Canvas; проверены её границы
строк и ΔY ≤ 2px. Во всех новых вводах Z ΔX/ΔY = 0/0.
`measure()` со старым layer после нативного ввода не используется.

## Блокер Enter и следующий этап

Chromium, свежий `A` (sentinel ещё не нужен), курсор в конце:

| Событие | DOM внутри span | readText() | offset |
| --- | --- | --- | --- |
| beforeinput insertLineBreak, cancelable=true | `A` | `A` | 1 |
| input insertLineBreak, cancelable=false | `A\n\n` | **`A\n\n`** | 2 |
| beforeinput insertText Z | `A\n\n` | `A\n\n` | 2 |
| input insertText Z | `A\nZ` | `A\nZ` | 3 |

Второй LF служебный: браузер заменяет его следующей буквой. Остановка сразу после
Enter оставляет неверный результат `readText()`. В Firefox после Enter DOM имеет
`<span>A\n<br></span>`; существующий индекс игнорирует конечный BR и читает `A\n`.
При исходном `A\n` со sentinel оба браузера добавляют один текстовый LF перед BR;
сразу после Enter текст `A\n\n`, offset 3, после Z — таблица выше.

Статический индекс Text/span/BR не различает пользовательский LF и временный LF
Chromium внутри Text. Безусловное удаление последнего LF испортит настоящий текст.
Следующий архитектурный этап — stateful-проекция канонической строки и Selection
по состоянию до операции, beforeinput/input, с проверками paste, удаления и IME.
Нормализация и история здесь не реализованы; интеграция WYSIWYG заблокирована.

## Совместимость и проверки

В обоих браузерах `alpha     beta gamma`, width 75: мышь на двух сторонах soft-wrap
даёт offset 8, ArrowDown → 15, ArrowUp → 8; Backspace/Delete удаляют ровно одну
UTF-16 единицу, native copy/paste удваивает исходный текст без виртуальных LF.
Firefox End и редкие caret-affinity расхождения из прежней матрицы допустимы как
технический долг. Одиночный CR остаётся расхождением Gate 0A; для неподдерживаемых
CR/CRLF нужен будущий fallback на существующий textarea, сохраняющий исходный
текст. Переписывание CR/CRLF, потеря текста и повреждение сохранения недопустимы.
Новый smoke не проверяет полноценный IME или persistence.
