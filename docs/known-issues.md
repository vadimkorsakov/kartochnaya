# Известные дефекты и архитектурные риски v0.45

База: `7623091139c2b8997067fd51de388918d64566cb`.
Все ссылки на функции и строки относятся к неизменённому
`kartochnaya v0.45/index.html`. На этапе 0 ошибки не исправляются.

## Воспроизводимые known failures

### KF-001 — внутренние ссылки при импорте отдельного документа

- Статус: подтверждён аудитом и повторно воспроизведён автоматическим тестом.
- Код: `importJSON`, строка 3473; `ensureGroupData`, 1775;
  `boundarySyncDoc`, 4913.
- Fixture: `tests/fixtures/linked-document.json`.
- Тест: `tests/known-failures.spec.js`, `KF-001`.
- Действия: импортировать документ с группой, фигурой и связанным boundary-текстом.
- Ожидание: `pathBoundary.sourceId` указывает на существующую фигуру;
  `groupId` слоёв указывает на соответствующий элемент `groups`.
- Фактически: ID элементов и `groupId` заменяются, а связанные `sourceId`
  и `groups[].id` не переназначаются согласованно. Обе проверки ссылок дают false.
- Последствия: теряется связь текста с фигурой; исходная группа и её свойства
  не соответствуют группе слоя. Синхронизация boundary может обнулить sourceId.

Тест читает сохранённую запись через readonly-транзакцию, а не подменяет модель.
Исправление должно рассматривать весь граф ссылок, включая слайды; этап 0 его не делает.

### KF-002 — потеря папок ресурсов при импорте проекта

- Статус: подтверждён аудитом и повторно воспроизведён автоматическим тестом.
- Код: `importProjectBackup`, строки 3455–3471, особенно сборка проекта на 3460;
  `resourceFolders`/`resourceFolderPath`, 3506–3508.
- Fixture: `tests/fixtures/project-with-folders.json`.
- Тест: `tests/known-failures.spec.js`, `KF-002`.
- Действия: импортировать проект с папкой и ресурсом внутри неё.
- Ожидание: список `resourceFolders` и ссылки `resources[].folderId` сохранены.
- Фактически: ресурсы с folderId копируются, список папок отсутствует.

Оба теста используют `test.fail()` только после успешного setup и проверки
предпосылок. Они проверяют правильный контракт, а не утверждают, что ошибка должна
существовать всегда. Неожиданное исправление приводит к unexpected pass и требует
снять метку known failure отдельным осознанным изменением. По умолчанию эти тесты
вынесены в отдельный проект и не входят в `npm test`.

## Другой подтверждённый дефект поставки

### KF-003 — manifest не подключён к HTML

Файл `manifest.webmanifest` существует, но в HTML нет `link[rel=manifest]`.
Service worker и офлайн-загрузка сами по себе не доказывают устанавливаемость PWA.
Основание: head HTML, регистрация service worker на строке 3818, manifest и sw.js.

Отдельный падающий тест устанавливаемости на этапе 0 не добавлен. Тест доступности
ресурсов не объявляется тестом установки PWA. Отсутствие ссылки записано среди
контрольных характеристик исходного HTML; manifest не подключается тестовым сервером.

## Ограничения текущего проверочного окружения

- **ENV-001:** управляемый Chromium запрещает `file://`. Тест отмечает skip только
  при точной ошибке `ERR_BLOCKED_BY_ADMINISTRATOR`, прикладывает объяснение и не
  выполняет оставшиеся проверки. Любая другая ошибка остаётся падением.
  `KARTOCHNAYA_REQUIRE_FILE_URL=1` превращает и это ограничение в падение.
- **ENV-002:** официальный `cdn.playwright.dev` возвращает `403 Domain forbidden`.
  Автоматическая установка браузера в этом окружении не подтверждена. Прогоны
  выполнены на установленном Chromium 154.0.8037.57 с явным executablePath.
  TLS и административные политики не отключались.
- Браузер сам запрашивает отсутствующий `/favicon.ico`. Тестовый наблюдатель
  игнорирует только console-resource-404 с этим URL; ошибки JS и остальных
  ресурсов не фильтруются. Новый favicon в релиз не добавлен.
