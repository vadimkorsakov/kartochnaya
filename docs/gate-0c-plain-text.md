# Gate 0C/3: plain-text WYSIWYG с проверкой совместимости раскладки

База: remote `main` `ac75b597ab0106955530086dd6ddc7a2e169116c`.
PR #75 объединён в main до начала работы.

## Результат и границы

Наличие непустого `textRuns` больше не является обязательным условием WYSIWYG.
Однако это **не общий допуск обычных слоёв**: цель для стандартного Arial 32
в этом PR не достигнута. По требованию задания несовместимые случаи оставлены
на legacy textarea. Предикат `usesRichTextLayout()` и оба Canvas-движка не изменены.
Строгие verdict Gate 0A/0B также не изменены.

Сохраняются URL-флаг `?experimentalTextWysiwyg=1`, desktop Chromium/Firefox,
горизонтальный текст с выравниванием left/top, разрешённые и загруженные шрифты,
отключённый auto-fit и прежние ограничения масок, эффектов, вращения и CR/CRLF.
Дополнительно для plain-text сравниваются реальные строки `wrapLines()` с
виртуальной раскладкой rich-text engine: содержимое, ширина, baseline и начало
строк. Допуск метрик — 0.5 document px (не более 1 screen px при 200%).
Неподдерживаемые метрики приводят к textarea.

Разделение цветом тоже разделяет Canvas shaping runs. Проверка plain-text
отклоняет строки, для которых advances соседней пары расходятся с отдельными
символами более чем на 0.5 px, и резервирует место для двух новых границ диапазона.
Суммарный допуск смещения от двух границ — до 1 document px; даже меньшая
потеря kerning недопустима, если она может добавить перенос. Это консервативное
ограничение: часть строк с достаточным запасом ширины тоже останется в textarea.
Декорации, mobileGlow и mobileBackground для новых plain-сессий не допускаются.
Изменение текста повторно проверяет совместимость; при её потере подтверждённый
текст и направленное UTF-16 выделение передаются штатному textarea.
Например, ввод `H` после `ABCD` остаётся в WYSIWYG, а ввод `X` создаёт пару
`DX` с kerning около 1.3 px в fixture Nimbus 26 и приводит к штатному handoff.
Это ограничение допущенных plain-сессий, а не обещание поддержки любого ввода.
Сессии, начавшиеся с runs, сохраняют прежнее поведение, включая полное удаление.

Реальный проверенный совместимый пример: загруженный **Nimbus Sans Regular,
26 px, lineHeight 1.03**, `ABCD`, а также `ABCD\nABCD`. Шрифт не подменяет Arial:
он поставляется только как воспроизводимый test fixture с лицензией upstream.
Решение принимается по метрикам установленного браузера, а не по названию шрифта
или разрешающему списку исключений.

## Модель и первое оформление

`richTextSpans()` уже представляет plain-text единым виртуальным span. Это
представление используется в DOM сессии; в документ ничего не добавляется.
Открытие, курсор, выделение и Ctrl+Enter без изменений сохраняют полную модель,
геометрию, отсутствие `textRuns` и `textRunsBaseFontSize`. Browser-тест наблюдает
реальные `IDBObjectStore.put` в docs и проверяет отсутствие дополнительных записей
и document history. Обычный ввод, его сохранение и повторное открытие тоже
сохраняют отсутствие runs.

Для совместимого `ABCD`, диапазона `[1,3)` и цвета `#11aa33` существующий
`applyTextStyle()` создаёт ровно:

```json
[{"start":1,"end":3,"style":{"textColor":"#11aa33"}}]
```

`text` остаётся `ABCD`, остальные символы наследуют слой. Референсный размер
при цвете не добавляется. Размер диапазона использует прежний механизм
`textRunsBaseFontSize`; шрифт, размер и цвет работают в той же сессии.
Preview, смешанная история ввода/оформления и Undo/Redo используют прежнюю inline
history. Undo первого оформления восстанавливает отсутствие свойства runs;
Redo возвращает диапазон. Escape восстанавливает полный исходный слой, включая
структуру. Нативный Undo input инспектора не перехватывается.

## Раскладка и воспроизводители исключений

В настоящем приложении browser-тесты наблюдают исходные `fillText()` с реальными
метриками и Range-геометрию DOM. Для пяти контрольных текстов на 50/100/200%
сравниваются Canvas-вызовы и точные пиксели до открытия и после неизменённого
закрытия. Для допущенных single-line и LF после первого цвета проверяются
baseline, шрифт, spacing, текст фрагментов; DOM содержит прежние размеры
неизменённых фрагментов. PNG-baselines не обновляются.

| Текст / условия | Результат |
| --- | --- |
| `ABCD`, Nimbus Sans 26 / lineHeight 1.03 | WYSIWYG в Chromium и Firefox; метрики в пределах допуска |
| `ABCD\nABCD`, те же условия | WYSIWYG; две строки, исходный шаг 26.78 px |
| `alpha beta gamma delta`, ширина 170, те же условия | textarea: консервативный guard строк/пробелов при переносе |
| `abcdefghijklmnop qrstuvwxyzabcdefghijklmnop`, ширина 170 | textarea: guard строк и shaping не допускает слой |
| `Группа  А😀Б`, Nimbus Sans 26, ширина 200 | textarea: сильный kerning на границе цвета |
| `ABCD`, Arial 32 / lineHeight 1.15 | textarea: несовместимые baseline |

**Arial 32:** старый baseline `24.828125`, rich `29.4`; сдвиг `4.571875`
document px, то есть `2.2859375 / 4.571875 / 9.14375` screen px на 50/100/200%.
Тест `plain Arial 32 transition reproducer` сначала проверяет отказ WYSIWYG и
точную модель после закрытия. Затем через реальное выделение в legacy textarea
и штатный color picker воспроизводит существующий переход к mixed Canvas,
подтверждая сдвиг между 4 и 5 px. Это проверка существующего дефекта,
а не утверждение, что переход визуально корректен.

**Nimbus Sans 32 в Firefox:** исходный baseline около `23.328`, rich `24`
(разница около `0.672 px`). Та же пара в Chromium даёт `23.328125` и `23`,
то есть проходит допуск. Отдельный browser-тест явно проверяет разные маршруты
редактирования в этих двух браузерах и точную модель после закрытия.
Это исключение не скрывается переносом всех проверок на другой размер.

**Kerning и граница цвета:** Nimbus Sans 32 / lineHeight 1, текст
`Группа  А😀Б`, `w=200`. До оформления строка имеет ширину около `198.65 px`.
Цвет `[1,3)` разделяет shaping на `Г`, `ру`, `ппа  А😀Б`; сумма advances
возрастает, и `А😀Б` может перейти на следующую строку. Поэтому одного сравнения
исходной виртуальной строки недостаточно; guard также проверяет advances
соседних символов и запас ширины для двух новых границ. Emoji не разделяются по surrogate pair. Известное
поведение emoji существующих rich-сессий проверяется прежними browser-тестами.

**Узкая рамка:** Nimbus Sans 32 / lineHeight 1, `ABCD`, `w=88`. Цельный текст
помещается в одну строку (87.80818 px), но первое оформление `[1,3)` разделяет
shaping и увеличивает ширину до 88.60818 px. Воспроизводитель через legacy UI
показывает две строки после цвета. Plain-guard заранее оставляет слой в textarea.

Эти исключения требуют отдельной работы над совместимостью Canvas-движков,
если нужно допустить стандартный Arial и произвольные plain-text строки.
Этот PR не меняет формат документа, IndexedDB, PNG-экспорт, mobile UI,
облачные функции, IME или CRLF и не объединяет Canvas-алгоритмы.

посылать ввод: Firefox может установить его в следующем animation frame.

агент не выполняет; после публикации Actions проверяются один раз без ожидания CI.
