# Rich Text — этап 1

`element.text` — единственный канонический текст. Необязательное `textRuns`:

```json
{
  "text": "Привет 😀",
  "fontFamily": "Arial",
  "fontSize": 24,
  "textRuns": [
    { "start": 0, "end": 6, "style": { "fontWeight": "700" } },
    { "start": 7, "end": 9, "style": { "textColor": "#ff0000" } }
  ]
}
```

Границы полуоткрытые, в кодовых единицах UTF-16, как у textarea.
Диапазоны упорядочены, не пересекаются, не выходят за текст. Соседние одинаковые
стили объединяются; пустые стили и значения, равные базовым свойствам слоя,
не сохраняются. У обычного текста поле отсутствует. Схема IndexedDB v3 прежняя.

## API: `src/model/rich-text.mjs`

Все функции чистые, возвращают новые данные и не обращаются к DOM/хранилищам.

- `normalizeRuns(text, runs, base?)`: отбрасывает повреждённые записи/значения,
  ограничивает границы текстом, устраняет пересечения; поздняя запись выигрывает
  по каждому ключу. Нормализация явная: чтение документа не переписывает данные.
- `validateRuns`: проверяет каноническое представление; отсутствие поля допустимо.
- `applyTextStyle(element, start, end, patch)`: разделяет диапазоны и применяет
  указанные ключи, сохраняя остальные; `null` удаляет переопределение.
- `removeTextStyle`, `clearTextFormatting`: удаление отдельных ключей или всего
  форматирования фрагментов (включая снимки диапазонов существующих мобильных команд).
- `splitTextRuns`: две части списка с границами относительно исходного текста.
- `replaceText(element, start, end, inserted?)`: вставка, удаление или замена.
  Вставка наследует стиль слева, в начале текста — справа. Замена наследует стиль
  первого заменяемого символа. Удаление сдвигает сохранившиеся диапазоны и объединяет
  соседей. Неформатированные промежутки остаются неформатированными.
- `updateText(element, nextText, hint?)`: адаптер обычного textarea, включая IME,
  вставку из буфера, автозамену. Подсказка из `beforeinput` различает одинаковые
  символы. Без подходящей подсказки используется минимальная одиночная замена
  между общими префиксом/суффиксом. При неоднозначных массовых заменах без подсказки
  невозможно восстановить намерение редактора; применяется это определённое правило.
- `effectiveTextStyleAt`, `effectiveTextStyles`: эффективный стиль символа или
  список сегментов, включая промежутки, с базовой типографикой слоя.
- `transformText`: отображение кодовых точек с сохранением стиля при изменении
  длины (например, `ß` → `SS`). Существующие мобильные регистр/списки сохраняют
  прежние текстовые результаты; их прежние raw-text снимки дополняются снимками
  диапазонов только у форматированных слоёв. Новых копий текста модель не вводит.

Непустые выделения расширяются до целой суррогатной пары; вставка внутрь пары
сдвигается к её началу. Код не разрезает суррогатные пары. Графемные кластеры
(комбинируемые знаки, ZWJ) не становятся новой системой индексации: сохраняется
совместимость с UTF-16 selectionStart/selectionEnd браузера.

## Расширение стилей

Имена базовых свойств совпадают со слоем: `fontFamily`, `fontWeight`, `fontStyle`,
`fontSize`, `textColor`, `letterSpacing`. Предусмотрены булевы `bold`, `italic`,
`underline`, `strikethrough`, `baselineShift` (super/sub или числовой сдвиг),
JSON-объекты `underlineDetails`, `strikethroughDetails`, `fontFeatures`,
`fontVariationSettings`. Булевы расширения не меняют существующий рендерер.
Новые JSON-совместимые ключи допускаются без смены формата; вложенность ограничена
16 уровнями. Опасные ключи прототипа и нечисловые/бесконечные значения отбрасываются.
`null` зарезервирован для удаления переопределений, не для хранения стиля.

`lineHeight` и `textAlign` запрещены в символьных диапазонах. Межстрочный интервал
остаётся свойством слоя; будущие абзацные диапазоны должны храниться отдельно.
Абзацная модель и интерфейс на этом этапе не вводятся.

## Совместимость и проверки

JSON, ZIP с SHA-256, IndexedDB, история, вкладки, слайды и graph-копирование уже
сохраняют полные объекты элементов. Их механизмы не изменены. Модель покрыта unit
тестами, включая реальные ZIP/IndexedDB и clone-функции. Браузерные тесты проверяют
общий редактор ПК/мобильного режима, повторяющиеся символы, IME-подобный input,
отмену, Undo/Redo, дублирование, вкладки, перезагрузку и неизменность PNG.
Физическая клавиатура Android/конкретные IME локально не тестировались.

Canvas, раскладка, переносы, PNG-экспорт и интерфейс не читают `textRuns` на этом
этапе. Смешанный рендеринг и визуальное выделение — последующие PR.
