## Механизм

`src/model/canvas-graph.mjs` — чистые операции над JSON-копиями. Двухпроходное
переназначение сначала выделяет ID элементов/групп, затем обновляет `groupId`,
`parentId`, `pathBoundary.sourceId`, `clipBaseId`. Остальные свойства, включая
вложенные параметры, имена, геометрию, fallback и отсутствующие необязательные поля,
сохраняются. При полном клонировании sourceLast сохраняется, чтобы прежняя
эффективная геометрия boundary не изменилась. Внутренние ID эффектов, градиентных точек и ресурсов не меняются.

Генератор проверяется на коллизии с исходными ID, ссылками, целевым холстом и уже
выделенными ID. Повторные ID внутри одного исходного холста отклоняются до записи;
нет попытки угадать, какой объект имелся в виду. Исторические одинаковые ID в разных
слайдах получают независимые отображения. Для root и активного слайда используется
одно отображение, без двойного переназначения. Их исходные поля копируются отдельно:
если старые представления уже расходились, ни одно не затирается другим.

Подключены `makeCardFrom`, `createWizardCardFrom`, `duplicateElement`, `copyLayers` /
`pasteLayers`, Canvas Alt+drag, `addTemplateSeries`, старый `createSeriesSlide`,
`zipOriginal_importJSON` и непосредственно связанный `duplicateDoc`.
`makeSlideFromDoc` остаётся копированием представления: при синхронизации root со
слайдом менять ID нельзя. Новый `makeTemplateSlide` выделяет ID при вставке шаблона.

## Частичное копирование

- Скопированная цель ссылки заменяется её копией.
- В том же исходном холсте доступная нескопированная цель сохраняется.
- Между документами/слайдами внешняя ссылка не переносится только по совпадению
  строки ID. Буфер содержит идентичность исходного холста в оперативной памяти.
- Без доступной фигуры boundary сохраняет геометрию/fallback, sourceId/sourceLast
  сбрасываются. Без основы обтравки снимается clipped и удаляется clipBaseId.
- Явно выбранные группы копируются с потомками, параметрами и родительскими
  связями. Одиночный слой сохраняет доступную исходную группу; в другом холсте
  снимает groupId. Несуществующие группы не создаются.
- У копий текстовых слоёв снимается H1. Полное клонирование документа сохраняет H1.
- Обтравленная копия с внешней основой вставляется в её существующую цепочку слоёв,
  поскольку рендер определяет маску по порядку. Для старого clipped-слоя без
  clipBaseId исходная основа вычисляется из существующей цепочки только в копии
  выделения. Исходный слой не дополняется. Общие правила рендера не изменены.

## Совместимость и отдельное восстановление

Схема IndexedDB v3, форматы ZIP/JSON, Web Locks, транзакции и восстановление ZIP
не изменяются. Облачные клиенты, OAuth, Service Worker и deploy не затронуты.
Открытие документа не вызывает новый механизм и не запускает миграцию.
Исторические файлы и PNG-эталоны не меняются.

Старые повреждения могут выглядеть как ссылка на прежний ID фигуры, автоматически
созданная безымянная группа вместо исходной, либо одинаковые ID разных слайдов.
Переназначение не восстанавливает уже утраченное соответствие. Полное клонирование
оставляет ранее неразрешённые ссылки как есть, без попытки связать их с новой целью.

Отдельная безопасная процедура восстановления: сначала экспорт неизменяемого ZIP,
затем readonly-диагностика и сравнение с известной исправной резервной копией;
пользователю показывается конкретный предлагаемый diff ссылок. При неоднозначности
выбор соответствия выполняет пользователь. Записывается отдельная восстановленная
копия через существующий транзакционный путь; исходный документ сохраняется.
Такая процедура и миграция в этот PR не входят.
