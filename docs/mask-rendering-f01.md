## Причины

1. `maskCanvasForLayer` возвращала белый Canvas при незагруженном `layerMaskSrc`.
   В `maskAlphaCanvas` он превращался в непрозрачную alpha-маску и сохранялся
   под тем же ключом, что и готовый PNG. `onload` инициировал paint, но не менял
   ключ: последующий paint повторно получал белую alpha-маску.
2. Размер исходного Canvas брался из `app.doc`; рендер миниатюры и PNG другого
   слайда получал другой `d`. При отсутствии активного документа готовая маска
   также не могла быть построена.
3. Alpha-ключ содержал только ID и source. Совпадающие исторические ID и PNG
   на разных размерах переиспользовали Canvas чужого размера. `getImageData`
   вне маленького исходного Canvas возвращал прозрачные пиксели.
4. `paintWithEffects` копировала весь backdrop, пропуская `destination-in`,
   пока изображение региона отсутствовало. Для обычного layer mask отсутствие
   alpha тоже означало рисование полностью немаскированного слоя.
5. Завершение загрузки обновляло активный Canvas и серию, но оставляло уже
   нарисованные библиотечные/диалоговые миниатюры устаревшими.
6. Выбор maskDraft только по строковому ID позволял использовать черновик
   другого холста. Редактирование исходного Canvas кэша также создавало alias.

## Исправление и правила кэшей

`src/render/image-resource.mjs` хранит в памяти состояние одного изображения:
`absent`, `loading`, `ready`, `error`. Один source запускает один Image и одну
completion Promise; ошибка завершает ожидающих и не запускает запрос заново при
каждом paint. Старые `{image, ready:true}` из существующего image pipeline
совместимы. Общая подготовка одного изображения пригодна для следующего F-03.

`src/render/layer-masks.mjs` получает фабрику Canvas и image reader; не знает
об `app`, DOM UI, истории или IndexedDB.

- Ключ готового grayscale/alpha результата: `JSON.stringify([source, width, height])`.
  Source — полная строка PNG/URL, размеры — размеры целевого документа.
  Отдельный documentId/layerId не нужен: одинаковое изображение при одинаковых
  размерах даёт одинаковую маску. Разные ID не вызывают лишних вычислений,
  совпавшие исторические ID не создают ложного совпадения.
- В ready-кэш попадают только готовые изображения или Canvas, явно сохранённый
  операцией редактирования. Loading/error не создают белой записи. Состояние
  absent допускает белый Canvas только как исходник команды создания маски.
- Новый PNG/source или размер означает новый ключ. Изменение/удаление маски,
  Undo/Redo и возврат к прежнему source выбирают соответствующую запись.
  Глобальная очистка всех кэшей не используется.
- Ready-кэш ограничен восемью записями с LRU-вытеснением. Пересоздание
  вытесненной записи использует уже готовый Image. Политика загрузки URL
  остаётся прежней: один ресурс на source; изменение содержимого удалённого URL
  без изменения строки не является версионированием маски.
- Редактор получает отдельную копию grayscale Canvas. `remember` тоже копирует
  вход, поэтому сохранённый результат не меняется вместе с живым черновиком.
- Черновики — отдельный WeakMap по объекту Canvas; версия и размеры выбирают
  alpha. При рендеринге исходная сущность слоя проверяется по identity внутри
  целевого документа, включая временные boundary-представления. Строка ID
  не связывает черновик с соседним документом/слайдом.
- Alpha сохраняет прежнюю формулу: округлённая luminance × исходная alpha.
  Формат layerMaskSrc и порядок эффектов не меняются. Готовый isFxRegion
  сохраняет прежнее применение alpha PNG выделения.

Неготовый/ошибочный masked layer не выводится; его эффекты тоже пропускаются.
Неготовый isFxRegion ничего не добавляет в backdrop. Загрузка/ошибка coalesced
через requestAnimationFrame обновляет актуальный Canvas, серию, открытую
библиотеку и открытый picker. Завершение старого запроса не выбирает активный
документ и не записывает данные в него.

Оба маршрута PNG ожидают только видимые layerMaskSrc целевого документа/слайда
перед paintDocument. При ошибке одиночный PNG не скачивается, пользователь видит
сообщение; серия использует существующее сообщение ошибки экспорта слайда.

Изменённые функции editor.js: `getImage`, `maskCanvasForLayer`,
`maskCommitCanvas`, `addLayerMask`, `removeLayerMask`, `maskFill`,
`maskPaintBegin`, `maskPaintSegment`, `maskPaintEnd`, `maskAlphaCanvas`,
`paintMaskedBase`, `fxRegionMask`, `paintWithEffects`, `paintDocument`,
`zipOriginal_exportPNG`, `zipOriginal_exportSeriesIndices`.
Добавлены `imageResource`, `imageSettled`, `prepareLayerMasks`.

## Проверка отсутствия мутаций / AR-001

Новый браузерный сценарий сравнивает целиком экспортируемый документ (включая
updatedAt), все записи `docs`, history HTML, количество UUID и вызовов
IDBObjectStore put/add/delete до/после async onload и zoom (все stores),
затем отсутствие записей docs при трёх PNG. Также сравниваются результаты
перерисовок и PNG. После команды PNG допускаются только исходные записи projects
со счётчиком имён. Все сравнения равны. Тест кисти проверяет отдельное
изменение PNG черновика, сохранение исходного PNG второго слайда и точный
Undo/Redo. Существующие 23 read-only сценария дополнительно проверяют
boundary-текст, неполные градиенты, историю со снимками, сохранение, миниатюры
серии и PNG без нормализации модели при чтении.

По явному уточнению пользователя существующая запись `project.exportCounters`
при явном PNG-экспорте сохранена:
это счётчик имён файлов исходной main, а не запись от Canvas-рендеринга.
Гарантия нулевых записей относится к документам и к пассивному рендерингу;
не заявляется нулевая запись всех stores при пользовательской команде PNG.
Схема IndexedDB v3, ZIP, облачные клиенты, OAuth и восстановление не изменены.

## Границы F-03 / AR-004

Общая централизованная подготовка rasterSrc, effects[].maskSrc, imageSrc,
FontFace и всего графа ресурсов не выполнена. Существующие imageSrc-ожидания
оставлены; эффекты maskSrc, растровые слои и шрифты могут требовать отдельной
подготовки на холодном PNG. Порядок композиции готовых эффектов не изменён.
Timeout/cancel/retry общей подготовки и обработка частично выгруженной серии
остаются отдельным дизайном экспорта. Image reader с общей completion позволяет
добавлять эти этапы без обхода кэша и дублирования Image для layerMaskSrc.

Merge и Production Deploy не выполняются.
