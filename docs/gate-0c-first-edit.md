# Gate 0C/4B: первое редактирование обычного текста

База: актуальный remote main `c7a68ed`. Эксперимент остаётся за
`?experimentalTextWysiwyg=1`, только desktop Chromium/Firefox.

## Причина

На main первое открытие plain-слоя проходит дополнительные проверки, которых
нет у старого unmarked rich-слоя. Поэтому первый ввод через textarea создавал
runs, а следующее открытие могло выглядеть исправленным само собой.

Конкретные блокировки:

1. `eligibleWysiwyg()` безусловно отказывал `autoFontSize`. Новые текстовые блоки
   создаются именно с этим свойством; сессия не запускала штатный auto-fit.
2. `plainWysiwygLayoutCompatible()` сравнивал legacy Canvas top baseline с rich
   baseline. Компенсация была жёстко ограничена Arial 32 / normal 400 /
   lineHeight 1.15. Arial 24 / lineHeight 1.3 без runs воспроизведён на main:
   все три новых теста первого оформления останавливались уже при открытии.
3. Даже допущенный слой передавался в textarea при частичном размере/шрифте:
   `applyRangeStyle()` требовал однородную `legacyTopProjection(next)`.
4. У стандартного lineHeight 1.1 font box может превышать legacy line step.
   Для нескольких строк это ограничивает допуск; у одной строки измеренная
   общая baseline позволяет точно совместить DOM и Canvas без смены painter.

## Исправление

Из PR #77 (`c5783cc`) адаптированы измеряемый допуск uniform LF-строк,
проверка суммы shaping двух новых границ и удаление ненужного маркера после
очистки последнего override. Старый PR не объединяется; его матрица,
результаты и изменения кэшей не выдаются за новые проверки.

Для одной непустой строки допускается частичная смена цвета, размера и
загруженного шрифта при совместимой геометрии. До изменения модели/истории
проверяются конечные Canvas-метрики, ширина строки, интервалы и стили
Canvas-фрагментов (включая границы grapheme), а также реальные CSS-baseline
и DOM Range advances. Ink bounds должны помещаться в рамку слоя: Canvas/PNG
обрезают её, а editable host показывает overflow. Допуск DOM/Canvas — 0.5 document px. Один общий offset
применяется к inline spans; native Selection и UTF-16 mapping сохраняются.
Каретка на границе стилей использует левый фрагмент, совпадая с правилом
наследования `replaceText()`. После LF сохраняется привязка к следующей
строке. Проверяются x, baseline и шрифт collapsed Range после ввода.
Font box может выходить за line box одной строки: следующей строки здесь нет,
а положение glyphs проверяется по фактической baseline. У uniform LF-строк
по-прежнему проверяется вместимость font box в шаг и одинаковая компенсация.

Auto-fit допускается, когда размер уже соответствует штатному расчёту на
копии слоя и геометрия проходит проверки. Открытие не пересчитывает исходник.
Ввод и оформление сначала запускают тот же auto-fit на следующей копии;
ручной частичный размер отключает auto-fit, как в обычном редакторе.
Undo/Redo восстанавливают сохранённый размер и флаг без нового пересчёта.

Preview, который затем требует textarea, откатывается к началу того же акта
перед handoff. Поэтому совместимый preview и несовместимое итоговое значение
не превращаются в две записи истории. Выделение передаётся вместе с направлением.

## Совместимость и границы

`element.text` остаётся каноническим; `textRuns` — sparse UTF-16 overrides.
Открытие/закрытие, выделение и no-op не создают runs, mode, Undo или IDB writes.
`legacy-top` записывается лишь при реальном частичном оформлении с необходимой
компенсацией. Старые unmarked rich-документы используют прежний baseline.
Два Canvas painter, PNG-эталоны, схема IndexedDB и формат экспорта сохранены.

Смешанная типографика нескольких строк, автоматический перенос нового режима,
несовместимые shaping/геометрия, glyphs за clip-рамкой, устаревший auto-fit размер, отсутствующий шрифт,
вращение, vertical/path, эффекты, маски и остальные прежние неподдерживаемые
свойства сохраняют textarea. IME использует прежний явный recovery; CRLF,
mobile и отсутствие URL-флага сохраняют fallback. Визуальные панели не меняются.

Измеренный пример оставшегося shaping-блокера: стандартный текст
`Ваш заголовок`, Arial 24 / lineHeight 1.1, Chromium 154 в этой среде.
Legacy baseline = 18.625 px; natural rich baseline = 22 px; font box = 27 px,
line step = 26.4 px. Single-row проекция устраняет это вертикальное расхождение.
Но пары `го` и `ол` имеют kerning по 0.52734375 px каждая; обе потенциальные
границы вместе меняют ширину на 1.0546875 px. Прежний guard 0.5 px сохраняет
textarea. Это отдельно воспроизводится браузерным тестом с точными Canvas
пикселями после no-op. Поэтому исправление не объявляется поддержкой всех
обычных строк. Следующий минимальный этап для этого примера — проверка
конкретных границ выбранного диапазона до plain→rich перехода и измерение
сформированных фрагментов против исходной строки; при недопустимой потере
shaping остаётся атомарный fallback. Общий guard сейчас не ослабляется.

Отдельный измеряемый предел auto-fit: Arial 24 / lineHeight 1.1 / h=28.
Частичный размер 16 помещается и работает сразу; размер 40 поднимает common
baseline примерно до 31 px, ниже нижней границы слоя. Такой акт атомарно
передаётся textarea с сохранением Selection/Undo, вместо демонстрации полного
DOM glyph при обрезанном Canvas/PNG. Следующий этап для этого случая —
совместимая с Canvas проекция clipping/прокрутки и native caret при overflow.

Следующий минимальный этап для mixed LF — измеряемая проекция каждой строки,
включая её CSS line box и общий baseline, с проверкой фактических переносов.
Единый offset всей сессии не доказывает совместимость такой раскладки.

## Проверки

В `tests/inline-wysiwyg.spec.js` добавлены сценарии без подготовительного ввода:
реальное обратное mouse-выделение [1,3), первый цвет/размер/шрифт на 50/100/200%,
native caret/DOM Range, ввод с наследованием sparse style, одна ступень Undo
на оформление, Redo, Escape, документная история, IDB, reload, повторное открытие
и native Canvas-вызовы реального PNG export. Отдельно проверяются стабильный
и меняющийся auto-fit, стандартный lineHeight 1.1, no-op без IDB writes,
очистка последнего override и атомарный handoff.

Firefox smoke включён в diagnostics job CI. Firefox Playwright не показывает
растровую native caret даже в изолированном contenteditable (прежнее измеренное
ограничение); его проверки используют native Selection/collapsed Range,
baseline и геометрию glyphs. Chromium дополнительно проверяет пиксели настоящей
каретки. Геометрия новых сценариев приложена как `first-edit-geometry.json`.

Локальные 12 сценариев Chromium (50/100/200% и auto-fit): legacy baseline
Arial 24 = 18.625 px. Максимальные отклонения DOM/Canvas: x = 0.01953125 px,
width = 0.01171875 px, baseline = 0 px; baseline collapsed caret = 0 px.
После первого цвета baseline Canvas меняется на 0 px. Это измерения из
`first-edit-geometry.json`, а не заданные константы проекции.

Firefox smoke: 38/38 passed. В 12 новых сценариях max DOM/Canvas x =
0.016619 px, width = 0.016680 px, baseline = 0.015195 px; baseline collapsed
caret = 0 px. Цвет сохраняет Canvas baseline (разница не более 4e-15 px).
Локальные браузеры запускались вне файловой песочницы с доступными
XDG_CONFIG_HOME/XDG_CACHE_HOME/TMPDIR; геометрические пороги не расширялись.
Длинные комплексные сценарии имеют timeout 90 s; локальные контрольные
прогоны также использовали CLI timeout 90 s из-за задержек загрузки/reload.

Фактические итоги локальных прогонов и GitHub Actions приводятся в PR.
Merge и Production Deploy не выполняются.
