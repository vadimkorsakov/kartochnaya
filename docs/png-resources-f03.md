# F-03 / AR-004: подготовка ресурсов PNG

База: `da53aca8fbe5fd964240d7e18fd16bef9200ab56` — актуальная main,
merge PR #36. Ветка: `fix/f03-png-resource-preparation`. Итоговый SHA и

## Воспроизведение на main

Сначала добавлены только браузерные тесты и исходное свидетельство,
commit `f7d2f03`. При воспроизведении bundle содержал исходный editor.js
из main, без исправлений. Команды:

```sh
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npx playwright test --project=chromium tests/png-resources.spec.js
```

**3 passed / 12 failed / 0 skipped / 0 expected failures.**
Результаты, ошибки и фактические RGBA —
[png-resources-f03-baseline.json](png-resources-f03-baseline.json).

Три контроля уже проходили: задержанный imageSrc (PNG ожидал готовность),
повреждённый imageSrc (файл не выпускался) и успешный холодный custom FontFace
700 italic (реальные glyph pixels совпадали с независимым Canvas и отличались
метриками от Arial). Они не объявляются новыми дефектами.

Подтверждённые причины:

1. `rasterSrc` вообще не ожидался. Задержанный полноразмерный красный растр
   выпускался белым `[255,255,255,255]`. После reload красный alpha=128 растр
   на синей обтравочной базе давал синий `[0,0,255,255]` вместо
   `[128,0,127,255]`; геометрия снаружи обтравки оставалась правильной.
2. `effects[].maskSrc` вообще не ожидался. Noise распространялся на внешнюю
   область: `[255,197,197,255]` вместо красного `[255,0,0,255]`.
   После загрузки маски горячий PNG отличался от первого.
3. Оба маршрута imageSrc создавали отдельные Image/decode поверх getImage.
   Общий source двух объектов давал два присваивания HTMLImageElement.src.
   Проверяется lifecycle объектов, поскольку HTTP-кэш браузера способен скрыть
   дублирование сетевых запросов.
4. Скрытая группа не исключалась из старого экспортного imageSrc-цикла;
   неисправный источник невидимого содержимого блокировал PNG.
5. Ошибка `loadFontFace` перехватывалась UI, но PNG не проверял требуемый
   пользовательский шрифт. Сохранённый старым JSON-импортом повреждённый face
   приводил к скачиванию PNG с fallback.
6. После await экспорт рисовал живую модель. Отдельный повтор теста с imageSrc
   (который main действительно ожидал) удалял слой и переключал документ до
   загрузки: вместо исходного красного PNG получался белый. Этот follow-up
   сохранён в том же baseline JSON отдельно от первоначального raster-сценария.

Сценарии combined, read-only и series также падали на неполных ресурсах.
Это не доказательство отдельной мутации модели или отдельного сбоя нумерации:
шаги после жёстких пиксельных assertions на main могли не выполняться.
Ранние прогоны при настройке fixtures (неверный выбор sample-документа,
проверка CSS-quoted family, старт сервера без сетевого разрешения) исключены
из baseline. Существующие тестовые исключения и PNG-эталоны не менялись.

## Перечень зависимостей реального рендерера

| Ресурс | Потребитель | Правило подготовки |
| --- | --- | --- |
| imageSrc | imageGeometry → imageInside; обычная, векторная и текстовая image-заливка | Если ветка рисует заливку; исключены открытые path, vectorLine и самостоятельный brush ribbon, сохраняется brush fallback |
| rasterSrc | paintElement, rasterCache либо getImage | Подтверждение через общий image reader, в том числе при отсутствии Canvas после reload |
| layerMaskSrc | paintWithEffects, paintMaskedBase, layerMasks, fxRegionMask | Только видимые по слою и всем группам объекты; размеры берутся из экспортируемого холста |
| effects[].maskSrc | fxSelectionMask → fxLimitMask/fxMixed, тени, текстовые и фоновые эффекты | Только включённые поддерживаемые эффекты; из фоновых эффектов используется первый согласно fxBackgroundEffect |
| family/weight/style, старое name | fontString, wrapLines, glyph/path/boundary/vertical/mobile/justify text, горизонтальный textBackdrop | Запрос конкретного начертания и регистрация требуемого custom FontFace |

У isFxRegion с эффектами источник — backdrop Canvas и layerMaskSrc, а не
image/raster-заливка. TextBackdrop у текстового региона может отдельно измерять
шрифт. Текст с fillType=none без stroke и textBackdrop шрифт не читает.
Скрытые группы/слои, отключённые и неизвестные эффекты не добавляют ресурсов.
Прозрачность сама по себе не исключает объект: эффекты и Canvas-композиция
могут продолжать читать его содержимое.

Проверены также vectorD/vectorParts (локальные строки Path2D), erasePaths,
inkPoints, gradient stops, шум/texture (синтетические Canvas), цвета,
геометрия boundary, background (цвет), обтравочные базы и mobile text effects.
Отдельных внешних URL у этих данных нет. Ресурсы библиотеки, обложки, UI-иконки,
шрифты меню и соседних/невыбранных холстов не являются зависимостями PNG.

## Координатор и существующие кэши

`src/render/export-resources.mjs` содержит чистый сборщик с портами visibility /
effect support и тестируемый `prepareCanvasResources`. Он не знает app,
IndexedDB, истории, DOM-диалогов или загрузок файлов. Возвращает `{ready:true}`
со счётчиками либо ExportResourceError с kind, source/layer или face descriptors
и причиной. Дубли изображений устраняются по source, текстовые требования —
по семейству/весу/стилю с объединением текста.

Все PNG-изображения идут через существующий
`src/render/image-resource.mjs`: тот же imgCache, Image и completion, которые
использует getImage. Независимых экспортных Image/decode и второго image-кэша
больше нет. Координатор последовательно ожидает подтверждённое состояние ready;
error, absent вместо ожидаемого источника и loading без completion — ошибка.
Правила готовых rasterCache/layerMasks и композиция эффектов не переписаны.

`src/render/font-resource.mjs` — общий registry существующего loadFontFace.
Ключ — source + регистрационное family + weight + style. Startup, JSON/font
upload, project import и PNG используют один lifecycle FontFace. Project import
по-прежнему сначала загружает лица, затем выполняет прежнюю транзакцию и только
после неё регистрирует их; экспорт не меняет транзакции или формат шрифтов.
Старое имя файла сохраняет прежние descriptors 400/normal.

Для custom family выбирается точное начертание либо совместимый CSS-порядок
подбора single-weight normal/italic/oblique лиц с сохранением синтеза при
отсутствии точного веса. Ошибочный exact face не заменяется соседним.
После face.load проверяются status, регистрация и фактический выбор через
FontFaceSet.load с нужными family/weight/style и текстом слоя. Ошибка другого,
неиспользуемого начертания не блокирует нужное. document.fonts.ready не служит
доказательством готовности конкретного ресурса.

## Асинхронный контракт

**Отделённый снимок модели.** Одиночный PNG копирует документ, metadata шрифтов,
название и ссылку на исходный project до первого await. Серия копирует их при
открытии диалога; активный root синхронизируется только в копию. Закрытие диалога
до подтверждения освобождает снимок, не создаёт PNG и не меняет счётчик.
После подтверждения диалог закрыт, операция продолжает выгрузку своего снимка.
Переключение вкладки, проекта, слайда, изменение/удаление слоя не меняет снимок.
Изменения попадут в следующую операцию. Краткий синхронный render исключает
fontPreview меню; transient preview другого документа с совпадающим ID не
подменяет шрифт PNG. Масочные draft другого объекта также не применяются к копии.

Одновременно выполняется одна PNG-операция в экземпляре редактора. Повторное
нажатие сообщает «PNG уже подготавливается», не занимает очередь и не меняет
нумерацию. Остальной интерфейс доступен. Это не глобальный UI-lock, не Web Lock
и не изменение механизма workspace/recovery.

На каждый холст действует общий deadline подготовки **15 секунд**, включая
шрифты. Есть AbortSignal для отмены ожидания координатора. Timeout/cancel
завершают ожидание, но не отменяют общий Image/FontFace, нужный редактору.
Истёкшая операция никогда не выпускает поздний PNG; новый экспорт может
переиспользовать завершившуюся загрузку. Фиктивной «готовности» по таймеру нет.

Слайды: collect → await → paint → toBlob → download, строго последовательно,
без Promise.all полноразмерных Canvas/PNG серии. При ошибке текущий файл не
создаётся, оставшиеся слайды не запускаются; уже подготовленные файлы сохраняют
успех и счётчик. Сообщение содержит и число успехов, и причину остановки.
Существующие имена сохранены: одиночный первый без номера, затем 1, 2; серия
начинает с counter+1. Счётчик увеличивается после передачи готового Blob браузеру.

## Неизменность и границы

Подготовка/рендер не записывают документы, history, updatedAt или IDB.
Экспорт выполняет только существующий persistProject для exportCounters,
включая его прежнее обновление project.updatedAt. Сравниваются полная JSON-модель,
сохранённые docs и history; существующие F-01 тесты дополнительно наблюдают все
IDB put/add/delete и UUID. Новые записи docs не допускаются.

IndexedDB v3, форматы ZIP/JSON, backup/OAuth/cloud/Web Locks/workspace recovery,
исторические файлы, PNG baselines и CI settings не изменены. F-04/F-07/F-05/F-06/
F-09 и независимый архитектурный долг не включены.

## Проверки и ограничения

Реальные браузерные PNG декодируются pngjs. Проверяются RGBA, геометрия,
alpha/обтравка, маски слоя/эффекта, холодный и горячий кэши, общие sources,
текстовые/векторные заливки, failure/no-download/no-counter, серия, dialog close,
переключение документа/проекта/слайда, удаление слоя, повторный click, timeout/retry.
Шрифты проверяются по всем пикселям независимого Canvas, реальным метрикам
в сравнении с Arial и status/descriptors FontFace, включая delayed cold startup
и legacy alias. Нет подмены рендера или прямой записи тестами в IDB.

Unit-тесты включены в test:unit: immutable inputs, полный сбор зависимостей,
dedup, shared load/hot cache, ошибки, timeout, AbortSignal, FontFace matching,
legacy aliases, отсутствие регистрации до import commit и failed exact face.
Результаты полного локального регресса и CI приведены в PR.

Остаются **3 ограничения проверки ресурсов**, без известного неполного PNG при
подтверждённой готовности:

1. FontFaceSet не доказывает наличие произвольного локального/системного семейства
   или каждого glyph. Семейство без записи в пользовательской библиотеке не
   объявляется custom. Если старый project importer уже отбросил неисправный
   шрифт, не оставив записи, экспорт не может восстановить его происхождение.
   Системный fallback и glyph fallback сохраняют совместимое поведение.
2. URL — идентичность ресурса в существующем кэше; изменение удалённых байтов по
   прежнему URL не является новой версией. Ошибочный ресурс сохраняет error до
   смены source/reload, автоматических повторных загрузок на каждом PNG нет.
3. Слишком медленный исправный ресурс может превысить 15 секунд: операция
   явно откажет. Общая загрузка продолжится; после её завершения доступен retry.
   Браузер также сам решает, разрешать ли множественные скачивания; счётчик
   отражает передачу подготовленных Blob, а не доказанную запись на диск.

Merge и Production Deploy не выполняются.
