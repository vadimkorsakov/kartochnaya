## Проверенные зависимости и контракты

| Функция | Вход → выход | Зависимости и особенности |
| --- | --- | --- |
| `rgbHex(r,g,b)` | Три компоненты → строка `#rrggbb` | `Number`, `Math`: округление, ограничение 0–255, falsy/NaN → 0, Infinity → 255 |
| `hexRgb(hex)` | Строка → массив трёх чисел | `slice`, `parseInt`: не валидирует и не нормализует, возможны NaN и частичный разбор; null/undefined/число вызывают TypeError |
| `hsvRGB(h,s,v)` | Градусы, проценты → массив целых RGB | Общий `clamp` из primitives; hue по модулю 360, отрицательные hue поддерживаются; s/v ограничены, NaN сохраняет исходное поведение |
| `rgbHSV(r,g,b)` | Три компоненты → массив `[h,s,v]` | Только Math и арифметика; дробные значения без округления, RGB не ограничивается |
| `rgbHSL(r,g,b)` | Три компоненты → массив `[h,s,l]` | Только Math и арифметика; дробные значения без округления, RGB не ограничивается |
| `hslRGB(h,s,l)` | Градусы, проценты → массив целых RGB | Тот же `clamp`; циклический hue, ограниченные s/l, исходное округление |
| `normalizeHex(raw)` | Значение → строка или null | String и RegExp; пробелы удаляются по краям; 6 цифр допустимы без #, 3 — только с #; короткая форма сохраняет регистр, полная становится строчной |
| `cpFormatValues(hex,format)` | Цвет и формат → массив чисел либо одной строки | `hexRgb`, `rgbHSV`, `rgbHSL`; RGB/HSB/HSL — три числа, CSS/HEX — одна строка; неизвестный формат ведёт себя как HEX |

Все объявления встречаются по одному разу. Побочных эффектов и зависимости от
DOM, `app`, Canvas, истории, IndexedDB или браузерных API нет. Возвращаются
новые массивы/строки либо null; входное состояние редактора не изменяется.
Внутри фрагмента нет второй реализации `clamp`.

Прежние потребители сохранены: цветовой интерфейс, градиентные остановки
и интерполяция, текстовые заливки/эффекты, CSS-ввод и пипетка. Их код не менялся.
Объявления функций остаются поднятыми в прежнем IIFE, поэтому вызовы из ранее
расположенных функций сохраняют доступ к тем же именам и к `clamp`.

## Сборка

`compileJavaScript` последовательно подставляет два фиксированных фрагмента:
primitives на прежнем месте после `clone`, colors после `syncTextFill` и перед
`currentPickerKey`. Сборка использует Buffer, не перекодирует и не форматирует
байты. Проверяются уникальность и порядок маркеров, LF и соседние объявления,
отсутствующие файлы, неизвестные/незавершённые и нерешённые маркеры.
Сохраняются исходные IIFE, порядок и область видимости. Новых глобальных
объектов, import/export и runtime-зависимостей нет.

Тесты временно меняют каждый вход `src/`, включая colors, и проверяют изменение
обоих дистрибутивов и совпадение HTML внутри ZIP с автономным HTML.
Удаление каждого JS-фрагмента останавливает сборку; fallback к историческому
релизу отсутствует. Перестановка, перенос, повреждение и дублирование маркеров
проверяются отрицательными примерами.

Побайтовое сравнение с историческим релизом относится к этому механическому
этапу. Оно не задаёт ограничений для будущей отдельной миграции на ES-модули.
