Новая ветка от main заменяет подход #110, а не продолжает его исключения.

## Воспроизведение до исправления

На исходники PR #110 временно добавлялась структурированная диагностика отказов
`plainWysiwygLayoutCompatible`, ошибок `project`, `requestFallback` и recovery.
Записывались слой, textRuns, UTF-16 selection, причина, строки Canvas, DOM,
computed font/line-height, font readiness и владелец фокуса. Диагностика удалена.

Браузеры запускали поставляемую сборку. Документ 1080×1350 и слой создавались
мышью и клавиатурой через UI; вставлялся настоящий clipboard-текст из issue
(268 UTF-16 единиц, без LF). Проверка точного текста обязательна: Firefox
Playwright `type`/`insertText` для кириллицы может симулировать composition,
поэтому для этого сценария используется реальный Ctrl+V.

Результат до исправления:

| Браузер | Автоподбор | Наблюдение |
| --- | --- | --- |
| Chromium | выкл. | Полные Georgia → Tahoma → Arial остаются live; Georgia для [20,90) вызывает textarea |
| Chromium | вкл. | То же; `uniform=false` при смешанной геометрии диапазона |
| Firefox | выкл. | Уже повторное открытие даёт textarea из-за проверки `row.width > w-1` |
| Firefox | вкл. | Полные шрифты live; шрифт диапазона вызывает textarea |

Фактический отказ Firefox: после drag рамка **737×633**, Arial **49 px**,
**11 строк**, суммарная высота **616 px**; первая строка **736,25 px**.
Она помещается в 737 px, но отвергается по порогу 736 px. Для смешанного
шрифта лог handoff содержит `selection={anchor:20,focus:90}` в Chromium,
`reason="Стиль недоступен в WYSIWYG"`. Действие затем записывается в textRuns
через textarea; textarea физически не может показать эти диапазоны.

## Первопричина и вся цепочка

UI/font picker сохраняет выделение; `styleInlineSelection` вызывает
`applyRangeStyle`. Модель и Canvas уже умеют смешанные стили и переносы,
но `project` строил обычные CSS spans и поручал браузеру заново переносить текст.
Это два разных алгоритма строк и базовых линий. Gate ограничивал размеры,
шрифты, пробелы и высоту, чтобы допускать лишь предполагаемое совпадение.
#110 расширял этот gate для однородной геометрии; смешанное форматирование
не устраняло архитектурное расхождение.

Отказ возвращался в `styleInlineSelection`, далее `requestFallback` →
`finishWysiwygFallback` → textarea. Подтверждённые textRuns сохранялись,
Canvas и PNG рисовали их, а textarea показывала только базовый стиль.
Повторный вход проходил тот же gate. Фокус сам по себе не был причиной этого
воспроизводимого handoff: лог сохранял конкретный диапазон.

Дополнительно изолирован настоящий метрический дефект Firefox: одинаковая
строка шрифта не гарантирует одинаковые метрики CSS и Canvas для дробного
размера. Например, `700 28.3125px Tahoma`, «Поэтому после выбора»:
DOM **343,2000**, Canvas **342,4333 px**; при `39.75px`, « шрифта »:
DOM **192,3000**, Canvas **193,5167 px**. Ошибка воспроизводится на пустой странице,
при identity/0.48 Canvas transform, с kerning auto/normal/none и разными
text-rendering. Кернинг не объясняет её. Измеренные Canvas размеры соответствуют
28.25 и 40 px; 65.5 соответствует 66, 129 — 128. Проверена общая представимая
двоичная точность объявлений, включая границы порядков.

В #110 уже есть длинная кириллица, но тест «long Cyrillic range remains live»
вызывает Ctrl+A и ожидает ровно один run на весь текст: он не проверяет
смешанный диапазон. Длинные фикстуры импортируются через seedPlain, используют
772 px / 31 px или 814 px / 61 px и viewport 2200×1600. Они обходят реальный
UI drag с рамкой 737 px / 49 px и пограничную ширину Firefox. Простые тесты
изменения шрифта проверяют однородную геометрию. Последующее авто-fit уже
смешанного сохранённого слоя с дробными run sizes и измерением каждого baseline
тоже не было покрыто. Поэтому зелёные результаты #110 не противоречат этому
воспроизведению.

## Реализация

- `supportsWysiwygProjection` проверяет поддерживаемые способы рисования,
  доступность метрик и конечность геометрии. Ограничений на soft wrap,
  смешанные шрифты/размеры, наличие LF, запас в 1 px и высоту больше нет.
- `project` использует те же строки, UTF-16 интервалы, x, высоты и базовые
  линии `richTextEngine.layout`, что Canvas/PNG. CSS больше не переносит текст.
  Структурные строки не добавляют символы; LF остаются исходными символами.
  Измеренный CSS baseline offset учитывается для каждого фрагмента.
- Строки и inline-фрагменты группируются для нативного выделения. Клавиши
  перемещения используют исходные grapheme boundaries и общие визуальные
  строки; Up/Down сохраняет желаемый x, Home/End — границы строки.
- Подтверждённые insert/paste/delete/Enter применяются к модели через
  `replaceText` до проекции. Браузер не сливает позиционированные строки и
  не создаёт разметку, из которой пришлось бы угадывать rich text. Copy/cut
  сериализуют исходный диапазон; cut — отдельное отменяемое действие модели.
- Range и whole-layer действия, line-height, рамка и переключение auto-fit
  проходят через историю сессии. Завершённые действия оформления разделены;
  ввод группируется только при публикации в историю документа.
  Явный размер выключает auto-fit; остальные изменения пересчитывают его.
- Нативная проба Canvas определяет точность backend без определения браузера
  по UA. На точном backend сохраняются прежние дробные объявления шрифтов.
  На backend с квантованием DOM/измерения/Canvas/PNG используют общую двоичную
  сетку (7 значащих двоичных бит, ties-to-even).
  Максимальное округление объявления — `fontSize/128`; **сохранённые размеры,
  textRuns, их reference size и масштаб не округляются и не мигрируются**.
  Arial 49, 42 и другие представимые размеры остаются точными.
- CSS kerning явно normal, как в Canvas. Обрезка редактора соответствует рамке.
  Полный исходный текст остаётся в модели и DOM даже за границами обрезки.
- Проверка шрифтов/узлов готовится до изменения модели; неудачная проекция
  не создаёт частичный input history entry. Неподтверждённый DOM/IME остаётся
  в явном recovery. Fallback сообщает причину и ограничение обычного поля,
  а не предлагает повторить якобы потерянное действие.

Формат документов, IndexedDB v3, сохранение и существующие Canvas/PNG
потребители общей раскладки сохранены. Изменения ограничены текстовой системой.

## Проверки и артефакты

`tests/multiline-wysiwyg.spec.js` проверяет UI-слой и clipboard, 5+ строк,
повторные полные шрифты, цвет, начертание, размер, range через строки, точные
UTF-16 offsets, нативное обратное выделение мышью, фокус HEX/numeric,
Undo/Redo в сессии/документе, resize/auto-fit во время ввода, JSON, IndexedDB,
reload/reopen, повторное форматирование сохранённого слоя и PNG.

Ожидаемую геометрию тест получает из настоящих native Canvas calls.
DOM измеряется настоящими Range rects и независимым baseline marker.
Шрифты/метрики/рендереры не подменяются. Проверяются текст каждого видимого
фрагмента, x, ширина, baseline, font, color, spacing; PNG дополнительно
декодируется, проверяются цветные пиксели и совпадение native paint calls.
Невидимые по обрезке исходные строки не объявляются нарисованными.
Порог DOM–Canvas — **0,25 px** (строже прежних 0,5/0,75), без обновления PNG.
`geometry.json`, снимки и failure traces сохраняются в test-results.

Старые тесты теперь проверяют поддерживаемую проекцию для прежних геометрических
fallback fixtures; проверки текста/истории/PNG сохранены или усилены.
Fallback/selection/history по-прежнему проверяются на действительно
неподдерживаемых rotation/opacity, отсутствующих метриках и unknown input.
Новые Chromium/Firefox E2E включены в существующий Actions diagnostics job.
Полный `test:all` оставлен GitHub Actions, локально не запускался.

Измерено на 212 фрагментах полного и частичного оформления, повторного входа,
reload, resize и нативного выделения: максимальные ошибки x **0,024495 px**,
ширины **0,024431 px**, baseline **0,027288 px** (объединение двух браузеров и
двух состояний auto-fit). Итоговые результаты локальных проверок также в PR.

## Ограничения и ручная проверка

Проверено на Linux, Chromium и Firefox; Windows Firefox из пользовательского
видео предстоит проверить на Deploy Preview. Нет заявления о побитовом
совпадении антиалиасинга двух браузеров: проверяются геометрия и оформление.
На backend с квантованием задание шрифта имеет описанную общую точность; исходные данные не меняются.

По-прежнему обычное поле: mobile/coarse/Safari, rotation, path/vertical text,
center/right/justify, masks/effects/stroke, unsupported run effects/unknown keys,
непрозрачность/градиент и CRLF. Реальная IME остаётся в явном recovery и не
объявлена поддерживаемой. Эти ограничения не маскируются разрешением gate.

Для ручной проверки: новый слой 738×634 на 1080×1350, абзац из #111,
масштаб около 50%, Arial 49 / 1.1. Выполнить Georgia → Tahoma → Arial,
красный цвет, bold, выделение через строки и другой размер. Повторить с auto-fit
в обоих состояниях, после resize, Undo/Redo, выхода/входа и reload. Сравнить
PNG и Canvas; отдельно проверить нативное выделение и ввод на Windows Firefox.
Merge, production и Production Deploy не выполнялись.
