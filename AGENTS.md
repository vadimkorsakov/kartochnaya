# КАРТОЧНАЯ: карта и правила работы

## Проект и приоритеты
- КАРТОЧНАЯ — локальный графический редактор карточек для ПК и Android.
- IndexedDB v3 — основной источник пользовательских данных.
- Локальное редактирование работает без интернета.
- Google Drive используется для необязательных ZIP-бэкапов.
- Данные пользователя важнее удобства рефакторинга.
- Merge выполняет пользователь, а не агент.

## Карта репозитория
- `src/editor.js` — основной редактор, пока монолитный.
- `src/index.template.html` — HTML-шаблон со встроенными Base64-иконками.
- `src/styles/` — стили.
- `src/core/` — цвета, градиенты, геометрия, фигуры.
- `src/storage/` — IndexedDB и транзакции.
- `src/model/` — проверка целостности проектов.
- `src/backup/` — ZIP-бэкапы и восстановление.
- `src/cloud/google-drive/` — OAuth, аккаунты и облачные копии.
- `src/pwa/` — Netlify PWA.
- `scripts/` — сборка и проверки.
- `tests/` — unit, browser и визуальные тесты.
- `docs/` — документация и история архитектурных решений.
- `kartochnaya v0.45/` — исторический исходник, а не текущий рабочий код.

## Как читать код
1. Сначала определи затронутую подсистему.
2. Читай её модули и связанные тесты.
3. Ищи конкретные функции через `rg -n`.
4. Выводи ограниченные диапазоны строк вместо огромных файлов целиком.
5. Не загружай весь `src/editor.js`, если достаточно нескольких функций.
6. Не читай Base64 Data URL и бинарные данные как текст без необходимости.
7. При обычной работе не читай исторический `kartochnaya v0.45/index.html`.
8. Не читай все старые `docs/*-v045.md` подряд.

Исключение: при задачах совместимости, миграции или изменения исторических
проверок читай необходимые архивные файлы и документы.
`.repomixignore` ограничивает только обзорные выгрузки Repomix; при целевом
историческом аудите явно включай нужные архивные файлы в анализ.

## Команды и тестирование
Требуется Node.js >=22. Команды определены в текущем `package.json`:
- `npm run test:source` — извлечение исходников и исторические контракты.
- `npm run test:unit` — core, IndexedDB, целостность, бэкапы и замена workspace.
- `npm run test:drive` — Google Drive, бэкапы и аккаунты.
- `npm run test:pwa` — PWA runtime.
- `npm run test:netlify` — сборка Netlify и браузерные проверки Netlify/Drive.
- `npm run test:visual` — визуальные тесты проекта chromium.
- `npm run test:bundle-smoke` — smoke-проверки standalone bundle.
- `npm run test:all` — все проекты Playwright; pretest выполняет сборку.
- `npm run build` — сборка поставки.
- `npm run build:verify` — проверка собранных артефактов.

Playwright настроен в `playwright.config.js`: проекты chromium, standalone,
known-failures; PNG-эталоны в `tests/baselines/`, обновление снимков отключено.
`playwright.netlify.config.js` наследует настройки и запускает проект netlify.
Если окружение предоставляет подходящий Chromium через
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`, используй его; не скачивай браузер заново
без необходимости. Для визуальных тестов учитывай `tests/baselines/environment.json`.
Перед интерпретацией падений читай `docs/known-issues.md`:
- KF-001 — дефект внутренних ссылок при импорте одиночного документа.
- KF-002 — исправлен.
- ENV-001 — возможная блокировка `file://` тестовой средой.
Не меняй expected failure, skip или PNG-эталоны ради зелёных тестов.

## Экономный рабочий цикл
1. Изучи минимально необходимые файлы.
2. Составь краткий план.
3. Сделай ограниченные изменения.
4. Выполни целевые проверки.
5. Исправь обнаруженные ошибки.
6. Один раз выполни необходимый полный регресс.
7. Создай PR и подготовь отчёт.

Не запускай полный Playwright после каждой небольшой правки.
Для добавления одних инструкций достаточно проверки содержимого и diff.
Не выводи огромные успешные логи, дампы JSON и Base64 в контекст.
При падении тестов сначала изучай конкретную ошибку.
Не выполняй несвязанные рефакторинги «заодно».

## Архитектурные ограничения
- Схема IndexedDB v3 не изменяется без отдельного задания.
- Нельзя молча удалять или переписывать пользовательские данные.
- Не отключай контроль SHA-256 и атомарность восстановления.
- Access tokens облачных хранилищ не записываются в постоянное хранилище.
- Исторические HTML/PWA ZIP изменяются только при явно разрешённом изменении
  соответствующего контракта.
- В `tests/source-extraction.test.mjs` существуют исторические diff-ограничения.
  Их удаление запланировано на T2, но НЕ входит в T1; diff-фикстуры сохраняются.

## Git и PR
- Работай от проверенной актуальной main, в отдельной ветке.
- Не считай локальный checkout актуальным без проверки.
- Если нужный commit уже есть локально, используй его без повторного скачивания.
- При ошибке `proxy:8080` не повторяй безуспешные попытки; используй разрешённый
  сетевой доступ Cloud Environment. Не отключай TLS и не меняй proxy environment.
- Не восстанавливай вручную весь репозиторий из GitHub API.
- Один PR на одну ограниченную задачу; Merge не выполняй.
- Не переписывай чужие коммиты и не изменяй PNG-эталоны автоматически.
- Перед PR выполни `git diff --check` и проверь состав изменённых файлов.
- Отчитывайся о фактически выполненных проверках.
- Отличай локальные результаты от GitHub Actions; дождись автоматического CI.
