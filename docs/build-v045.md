# Автоматическая сборка v0.45 — этапы 1–2

## Скачать через GitHub без установки программ

1. После проверки объедините PR этапа 2 в `main` кнопкой Merge на GitHub.
2. Откройте репозиторий → **Actions** → **Build HTML and PWA**.
3. Откройте последний успешный запуск с зелёной галочкой для `main`.
   При необходимости нажмите **Run workflow**, выберите `main` и подтвердите запуск.
4. Внизу страницы запуска, в **Artifacts**, нажмите
   **kartochnaya-v045-distributions** (нужно войти в GitHub с доступом к репозиторию).
5. Распакуйте скачанный контейнер артефакта. Внутри находятся `kartochnaya.html`
   и `kartochnaya-pwa.zip`. HTML можно открывать отдельно. Для хостинга распакуйте
   внутренний PWA ZIP и загрузите его содержимое в одну папку; `index.html`
   должен находиться прямо в выбранной папке, в том числе в подкаталоге сайта.

Артефакты хранятся 30 дней; после истечения срока запустите workflow ещё раз.
Запуск на main автоматический только при изменении входов сборки или workflow;
правки одних текстовых инструкций не создают лишних запусков.
Ничего не публикуется в интернете, приватность репозитория не меняется.
Если Actions отключён политикой аккаунта, владелец должен разрешить Actions и
официальные actions/checkout, actions/setup-node, actions/upload-artifact через
Settings → Actions → General (или обратиться к администратору организации).

## Команды для среды разработки

Node.js закреплён в `.node-version`, зависимости — в существующем lockfile.

```
npm ci
npm run build
npm run build:verify
```

Можно отдельно выполнить `npm run build:html` или `npm run build:pwa`.
Проверка требует наличия обоих результатов. `dist/` не хранится в Git.
Новых зависимостей нет, lockfile не изменён. Скрипты используют только Node.js,
не требуют Bash, Python или системного zip. Архив без сжатия немного больше,
зато не зависит от версии компрессора.

`build:verify` проверяет все 19 исходных файлов по контрольному манифесту этапа 0,
побайтовое равенство HTML и точное содержимое и метаданные ZIP. При нарушении
проверка завершается ошибкой и workflow не выдаёт артефакты.

ZIP содержит 18 runtime-файлов, без README, тестов и зависимостей. Порядок имён
стабилен, пути UTF-8 с `/`, timestamp 1980-01-01 00:00:00, метод STORE, платформа
DOS, без комментариев, extra fields и атрибутов ОС. HTML собирается из `src/`
через `scripts/compile-html.mjs`: маркеры заменяются буферами CSS и JavaScript
без декодирования и преобразования строк. `.gitattributes` сохраняет байты
исторического релиза и `src/` при checkout на Windows.
`npm run test:source` проверяет точность извлечения, ошибки маркеров, использование
каждого входа в обоих дистрибутивах и повторяемость сборки. Workflow выполняет
эти проверки перед сборкой. Минификация и функциональный рефакторинг не выполняются.

Для браузерных проверок: `npm run test:build` или `npm run test:all` (оба сначала
собирают результаты). В данной среде перед командой задаётся
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`; на Windows переменная
задаётся средствами используемой оболочки. Общий прогон использует неизменённые
PNG-эталоны и инфраструктуру этапа 0. Полный прогон проверяет ZIP и отдельный HTML; workflow проверяет сборку без браузера.

## Оставшиеся ограничения

- KF-003: HTML не подключает manifest. Комплект PWA сохраняется, но полная
  устанавливаемость не подтверждена. Работа service worker не является её проверкой.
- KF-001 и KF-002 и архитектурные риски этапа 0 не исправлялись.
- При HTTP-размещении только автономного HTML браузер сообщает 404 для `sw.js`:
  исходный код пробует зарегистрировать worker. Проверка фиксирует именно это
  предупреждение отдельно; ошибок JavaScript, мешающих редактированию, нет.
- `file://` в управляемом Chromium запрещён политикой ENV-001. Проверка запуска
  с диска на реальном устройстве остаётся необходимой; политика не отключалась.
- Linux/Chromium проверен автоматически. Новые прогоны на Windows и Android
  не выполнялись; сохранение байтов не заменяет испытания на этих устройствах.
