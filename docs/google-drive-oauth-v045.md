# Google Drive OAuth — КАРТОЧНАЯ v0.45, этап 14Б

Google Drive доступен только в Netlify-дистрибутиве. На этом этапе приложение
подключает аккаунт и проверяет доступ; оно не загружает ZIP, не создаёт файлы,
не синхронизирует проекты и не переносит локальную IndexedDB в облако.
Историческая HTML-версия и скачиваемый PWA ZIP не содержат этой интеграции.

## Настройка Google Cloud

1. Открой <https://console.cloud.google.com/> под своим аккаунтом. Создай отдельный
   Google Cloud проект или выбери предназначенный для КАРТОЧНОЙ проект.
2. В **APIs & Services → Library** найди **Google Drive API** и включи его именно
   в этом проекте.
3. Открой **Google Auth Platform** (в старом интерфейсе **OAuth consent screen**).
   Заполни Branding: название приложения, email поддержки и контакт разработчика.
   В Audience выбери подходящую аудиторию; для личного испытания — External / Testing.
   В Data Access добавь только
   `https://www.googleapis.com/auth/drive.file`. Более широкие Drive scopes не нужны.
4. В Audience / Test users добавь Google email, которым будешь подключаться.
   Пока приложение в Testing, используй добавленного тестового пользователя.
   Организационные политики Workspace могут отдельно ограничивать доступ.
5. В **Clients → Create client** (или **Credentials → Create credentials → OAuth
   client ID**) выбери **Web application**.
6. В **Authorized JavaScript origins** добавь точно:
   `https://kartochnaya.netlify.app` — без завершающего `/`, пути и query.
   Сохрани и скопируй Client ID с окончанием `.apps.googleusercontent.com`.
   Redirect URI для GIS Token Model не требуется. Для другого HTTPS-домена или
   Deploy Preview добавляй его собственный origin отдельно, если он нужен.
7. Не включай Powered by Netlify badge / HUD: он ранее изменял HTML после сборки
   и нарушал SHA-256 при установке service worker. Механизм проверки целостности
   остаётся обязательным.

## Подключение на настоящем Netlify-адресе

После merge и успешного Netlify deploy открой
<https://kartochnaya.netlify.app>, дождись «Готово к работе офлайн». Если открыта
старая PWA, выполни предложенное обновление. На главной открой «JSON и копии»
и карточку **Google Drive**:

1. Нажми **Настроить Client ID**, вставь свой публичный Web application Client ID
   и сохрани. Пустое поле сбрасывает настройку. Смена ID сбрасывает текущий сеанс.
2. Нажми **Подготовить авторизацию**. Только сейчас загружается официальный
   `https://accounts.google.com/gsi/client`.
3. После подготовки отдельным нажатием выбери **Подключить Google Drive**.
   Выбери тестовый аккаунт и разреши `drive.file` в окне Google.
4. Дождись **Google Drive подключён — имя/email**. Этот статус появляется только
   после проверки предоставленного scope и успешного
   `GET https://www.googleapis.com/drive/v3/about?fields=user(displayName,emailAddress)`.
   Имя берётся из ответа Drive, при отсутствии имени используется email; Google
   может не вернуть эти поля. Другие profile/email scopes не запрашиваются.
5. **Отключить** удаляет токен и сведения об аккаунте из памяти. Приложение не
   отзывает разрешение Google. При необходимости пользователь может отдельно
   удалить разрешение в настройках доступа своего Google-аккаунта.

Этот PR не выкладывается в production и не объединяется автоматически. Реальное
подключение требует собственного настроенного Client ID и ручного входа владельца;
CI не использует настоящий Google-аккаунт.

## Что хранится и как работает Token Model

Client ID — публичный идентификатор приложения, его допустимо использовать в
браузере. **Client secret — секрет сервера; он здесь не требуется, не вводи его
в КАРТОЧНУЮ и не добавляй в репозиторий.** Client ID хранится отдельным ключом
`kartochnaya-google-drive-client-id` в localStorage этого браузера/origin.
Он не входит в разрешённый список настроек ZIP рабочего пространства.

GIS использует `google.accounts.oauth2.initTokenClient`, только scope `drive.file`
и `include_granted_scopes: false`. Access token живёт только в памяти вкладки,
передаётся исключительно в Authorization Bearer header к Drive API, не попадает
в URL, IndexedDB, localStorage, sessionStorage, ZIP, журналы и Netlify Functions.
Нет client secret, refresh token, OAuth-прокси или собственного implicit flow.
GIS может использовать собственные механизмы Google для входа; приложение не
управляет Google cookies.

После reload, закрытия страницы, ухода в офлайн, отключения или смены Client ID
сеанс сбрасывается. По `expires_in` доступ истекает; возврат во вкладку также
проверяет срок, если браузер задержал таймер. При 401 токен немедленно сбрасывается.
Для нового доступа нажми **Подключить повторно**. Автоматических OAuth-запросов,
обновления токена и фонового восстановления сеанса нет. Разрешение `drive.file`
относится к файлам приложения; этот этап вообще не выполняет файловых операций.

## Ошибки и офлайн

- **origin_mismatch**: проверь origin текущей вкладки, тип клиента Web application
  и Authorized JavaScript origins в том же Google Cloud проекте. После изменения
  настроек Google может потребоваться время. Не добавляй путь `/index.html`.
  GIS иногда показывает эту ошибку в самом popup: закрой окно и проверь настройки.
- **Popup заблокирован**: разреши всплывающие окна для сайта. После загрузки GIS
  нужно отдельное нажатие подключения, не автоматический запуск из Promise.
  Закрытие окна и отказ в разрешении освобождают интерфейс для повторной попытки.
- **403 / недостаточно разрешений**: подключись повторно и предоставь `drive.file`.
  **403 / API отключён**: включи Google Drive API для проекта Client ID. Прочие
  запреты могут зависеть от администратора Workspace, квот и политики аккаунта.
- **Нет сети / загрузка GIS не удалась**: проверь сеть и блокировщики. Загрузка GIS
  и запрос Drive ограничены 15 секундами; ожидание OAuth — 2 минутами. Повторные
  нажатия блокируются во время операции. Смена ID/отключение отменяют проверку;
  запоздалый callback не подтверждает старый сеанс.
- **file://**: авторизация не поддерживается. Если открыть скопированную
  Netlify-страницу локально, карточка сообщает об этом и не запускает Google.
  В обычных HTML/PWA ZIP этой карточки нет.

При обычном запуске нет запросов к Google. Проекты открываются и редактируются,
IndexedDB сохраняет изменения, JSON и ZIP работают без сети. Для повторного запуска
сайта офлайн сначала необходим полный проверенный офлайн-кэш. Service worker
не кэширует GIS, Google API, токены или пользовательские данные; его алгоритм
обновления и SHA-256 проверки не меняются.

## Проверки

`npm run test:drive` запускает контролируемые тесты сеанса без аккаунта Google.
`npm run build:netlify` и
`npx playwright test --config=playwright.netlify.config.js tests/google-drive.spec.js`
проверяют интерфейс с имитацией GIS/Drive. `npm run test:netlify` включает эти
проверки вместе с полной готовностью PWA, офлайн-редактированием, JSON/ZIP и
обновлениями. CI выполняет оба набора. PNG-эталоны не обновляются.

В управляемом Chromium этой среды действует ENV-001: навигация `file://`
блокируется политикой администратора. Браузерный сценарий помечается skip только
для `ERR_BLOCKED_BY_ADMINISTRATOR`; для строгого запуска вне этой среды задай
`KARTOCHNAYA_REQUIRE_FILE_URL=1`. Отказ запуска OAuth в неподдерживаемом контексте
дополнительно проверяется тестом сеанса; этот тест не заменяет настоящий file://.
