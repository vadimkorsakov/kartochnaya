# Этап 2: механическое извлечение исходников v0.45

## Что изменилось

Рабочие исходники теперь находятся в `src/`:

- `index.template.html` — исходная разметка, внутри исходных тегов заменены только три содержимых блока.
- `styles/legacy-01.css` — первый блок style, 168 735 байт.
- `styles/legacy-02.css` — второй блок style с id v044-fixes, 530 байт.
- `editor.js` — весь исходный script, 525 661 байт; общий IIFE сохранён.

Код, CSS, повторные объявления, обёртки и порядок обработчиков не изменялись.
Изображения, SVG и data URL остаются на своих местах. Форматирование и оптимизация
не выполнялись. Каталог `kartochnaya v0.45/` остаётся историческим эталоном,
его HTML больше не является входом сборки. Из него берутся остальные PWA-ресурсы.

`scripts/compile-html.mjs` читает файлы как Buffer и заменяет три точных маркера:
`{{KARTOCHNAYA:LEGACY_01_CSS}}`, `{{KARTOCHNAYA:LEGACY_02_CSS}}`,
`{{KARTOCHNAYA:EDITOR_JS}}`. Они должны занимать исходные теги и идти в исходном
порядке. Пропущенный, повторный, неизвестный, незавершённый или перемещённый
маркер останавливает сборку. Дополнительных переводов строк и комментариев нет.
`.gitattributes` запрещает преобразование строк в `src/` при Windows checkout.

Оба дистрибутива получают один собранный HTML. В готовом HTML весь код и стили
встроены; внешние исходники для запуска не требуются. Упаковщик ZIP этапа 1
не изменён. В архиве прежние 18 runtime-файлов; README исторического релиза
в архив не включается. Service worker и manifest сохранены.

## Команды и защита от возврата к старому HTML

```
npm ci
npm run test:source
npm run build
npm run build:verify
```

Отдельные `build:html` и `build:pwa` продолжают работать. Сборочные скрипты
используют стандартную библиотеку Node.js, не требуют Bash или новых зависимостей.

Три теста `test:source` проверяют все байты извлечённых блоков и шаблона,
некорректные маркеры и отсутствующие входы, повторяемость полной сборки и
равенство отдельных целей. Во временной копии поочерёдно меняется каждый из
четырёх исходников: оба результата обязаны измениться, а index.html в ZIP —
совпасть с новым HTML. Отсутствующий editor.js обязан остановить сборку;
подстановки исторического HTML нет. Рабочие исходники при этих пробах не меняются.

`build:verify` сравнивает результат с актуальным `src/`, историческим HTML,
двумя SHA-256 этапа 1 и каноническим ZIP; проверяет исходные файлы релиза
по неизменённому манифесту этапа 0.

## GitHub Actions и действия владельца

Обновлён прежний workflow **Build HTML and PWA**: добавлены `src/**`, сборщик
и тест исходников в фильтры изменений, перед сборкой запускается `test:source`.
Сохраняются проверка сборки и скачиваемый артефакт с HTML и PWA ZIP на 30 дней.
Нового workflow, публикации или изменения приватности нет.

Реальный запуск обновлённого workflow в GitHub Actions в этой задаче пока
не подтверждён: чтение запусков через `gh run list` получило `Forbidden`.
Локально те же команды установки, проверки исходников, сборки и проверки
результатов прошли успешно. Это не заменяет подтверждения запуска на GitHub.

Владелец может открыть PR, просмотреть изменения и объединить его в main.
После этого открыть Actions → Build HTML and PWA, дождаться зелёного запуска
и скачать `kartochnaya-v045-distributions`. До объединения можно вручную выбрать
ветку `refactor/v045-source-extraction` в Run workflow и проверить её сборку.
Подробная инструкция: [build-v045.md](build-v045.md). Самостоятельного Merge нет.

## Оставшиеся ограничения и следующий этап

KF-001 и KF-002 воспроизводятся; KF-003 (отсутствие manifest-ссылки) сохранён.
Исходные архитектурные риски не исправлялись. При размещении единственного HTML
по HTTP сохраняется предупреждение о 404 для sw.js, отдельно записанное в отчёт.

сборки переносимы, а байты защищены .gitattributes. Проверка file:// требует
среды, разрешающей локальные файлы.

Следующий этап рекомендуется начать с дополнительных тестов зависимостей
и порядка выполнения JavaScript, затем отдельно проектировать осторожное
выделение подсистем из IIFE. Этап 3 требует нового задания и здесь не начат.
